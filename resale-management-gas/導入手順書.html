A. 準備

約5分
01

用意するものを確認する

  • 会社のGoogleアカウント（Google Workspace）。個人のgmailではなく、会社ドメインのアカウントを使ってください。
  • ソースコード4ファイル。同梱のzipを展開しておきます。
  • 営業日報のCSV（1日分でかまいません）。動作確認に使います。
!

作業するアカウントは慎重に選んでください。ここで使ったアカウントがシステムの持ち主になります。 個人アカウントで作ると、その人が退職・異動したときにシステムごと使えなくなります。

可能であれば、部署の共有アカウントか、長く在籍する管理者のアカウントで作業してください。

02

スプレッドシートを新規作成する

ブラウザで sheets.new を開くと、空のスプレッドシートが1枚できます。

左上のファイル名（無題のスプレッドシート）をクリックして、 わかりやすい名前に変えておきます。例：46期 未成約リセール管理

i

このスプレッドシートがデータの保管場所になります。あとから中身を直接見ることもできますが、 日常の入力はすべてこれから作る画面から行います。

✓ここまでで確認できること

  • 名前をつけた空のスプレッドシートが1枚できている

B. コードを入れる

約10分
03

Apps Script の画面を開く

作ったスプレッドシートのメニューから開きます。

メニュー操作 拡張機能›Apps Script

新しいタブでコードの編集画面が開きます。左側に コード.gs というファイルが1つだけある状態です。

これから、この画面に4つのファイルを作っていきます。

Codeデータの取得・保存・権限判定など、裏側の処理スクリプト
InitSheetシートを自動で組み立てるスクリプトスクリプト
Index画面の見た目HTML
Javascript画面の動きHTML
!

ファイル名は上のとおり正確に入力してください。 とくに Index と Javascript は、名前が1文字でも違うと画面が真っ白になります （システムがこの名前でファイルを探しに行くためです）。

04

Code を貼り付ける

  1. 左のファイル一覧で コード.gs をクリックします。
  2. エディタに表示されている中身をすべて選択して削除します（Ctrl+A → Delete。Macは ⌘+A）。
  3. zip内の Code.gs をテキストエディタで開き、全文をコピーして貼り付けます。
  4. ファイル名を変えます。コード.gs の右の ⋮ → 名前を変更 → Code と入力。
i

スクリプトのファイル名（Code / InitSheet）は多少違っても動きます。 厳密に合わせる必要があるのは Index と Javascript の2つだけです。

05

InitSheet を追加する

ファイル追加 ファイル の ＋›スクリプト
  1. ファイル名に InitSheet と入力して確定します。
  2. できたファイルの中身をすべて削除し、zip内の InitSheet.gs の全文を貼り付けます。
06

Index を追加する（HTML）

ファイル追加 ファイル の ＋›HTML
  1. ファイル名に Index と入力して確定します。
  2. できたファイルの中身をすべて削除し、zip内の Index.html の全文を貼り付けます。
!

ここは「スクリプト」ではなく「HTML」を選んでください。間違えると画面が表示されません。

07

Javascript を追加する（HTML）

ステップ06と同じ手順で、HTML を選び、ファイル名を Javascript にして、 zip内の Javascript.html の全文を貼り付けます。

!

こちらもHTMLです。名前は Javascript（先頭だけ大文字、あとは小文字）。 JavaScript のように S を大文字にすると動きません。

08

保存して、ファイル構成を見直す

画面上部の 💾 保存（または Ctrl+S）を押します。

左のファイル一覧が、次の4つになっていることを確認してください。

ファイル名種類貼り付けた内容
Code.gsスクリプトCode.gs
InitSheet.gsスクリプトInitSheet.gs
Index.htmlHTMLIndex.html
Javascript.htmlHTMLJavascript.html

エディタに赤い波線やエラー表示が出ていなければ大丈夫です。

✓ここまでで確認できること

  • Apps Scriptの左側に、4つのファイルが並んでいる
  • HTMLの2つが Index と Javascript という名前になっている
  • 保存済みで、エラー表示が出ていない

C. シートを自動で作る

約5分
09

スプレッドシートを開き直してメニューを出す

スプレッドシートのタブに戻り、ブラウザでページを再読み込みします（F5）。

読み込みが終わると、メニューバーの右端に新しい項目が増えます。

増えるメニュー 46期未成約ダッシュボード

この中に、次の2つが入っています。

  • ① 全シートを初期化（InitSheet） — 最初に1回だけ使います
  • ② AI分析用サマリを作成／更新（Gemini用） — 運用開始後に使います
!

メニューが出ないときは、Apps Scriptの保存ができていない可能性があります。 もう一度保存してから、スプレッドシートを再読み込みしてください。

10

初回だけ、権限の承認をする

メニューから ① 全シートを初期化（InitSheet） をクリックします。 初回は「承認が必要です」というダイアログが出ます。これは正常です。

  1. 権限を確認 をクリック
  2. 作業しているアカウントを選ぶ
  3. 「このアプリはGoogleで確認されていません」と出たら、 左下の 詳細 → （安全ではないページ）に移動 をクリック
  4. 内容を確認して 許可 をクリック
i

「確認されていません」という警告について。 これは、Googleの審査を受けていない自作スクリプトすべてに表示されるものです。 自分で作ったスクリプトを自分で許可しているだけなので、問題ありません。

ここで求められる権限は「このスプレッドシートを編集すること」と 「ウェブアプリとして画面を表示すること」です。

11

全シートを初期化する

承認が終わると処理が走ります（数十秒かかることがあります）。 完了すると シート構築が完了しました というメッセージが出ます。

スプレッドシートの下部に、次のシートが自動で作られます。

シート名役割
店舗名 ×10枚店舗ごとの未成約データ（CSVはここに入ります）
店舗別サマリ店舗×月の集計表（自動計算）
個人別サマリ(上期)/(下期)個人集計のレイアウト
店舗マスタ店番と店舗名の台帳
スタッフマスタ社員とGoogleアカウント・権限の台帳
i

このメニューは何度実行しても安全です。 すでにあるシートは中身を残したまま、足りない見出しだけを補います。 データが消えることはありません。

!

このフェーズCを飛ばすと、公開後の画面が動きません。 「店舗マスタ シートが見つかりません」というエラーが出ます。

その場合でも復旧できます。公開した画面の上部に 初期セットアップを実行する というボタンが出るので、 それを押せばこのステップ11と同じ処理が走ります。 スプレッドシートのメニューからでも、画面のボタンからでも、どちらでも構いません。

✓ここまでで確認できること

  • シートのタブが15枚前後に増えている
  • 店舗マスタ に10店舗が入っている
  • スタッフマスタ の見出しが「営業所コード / 社員番号 / 社員名 / Googleアカウント / 権限レベル / 有効」になっている

D. 画面を公開する

約10分
12

ウェブアプリとして公開する

Apps Scriptのタブに戻り、右上のボタンから進みます。

公開操作 デプロイ›新しいデプロイ ›⚙ 種類の選択›ウェブアプリ

設定欄が出たら、次のとおりに指定します。

項目設定する値
説明任意（例：初回公開）
次のユーザーとして実行自分（自分のメールアドレス）
アクセスできるユーザー組織内の全員（会社のドメイン名が表示されます）

デプロイ を押すと、ウェブアプリのURLが表示されます。 これがみんなに配るURLです。コピーして控えておいてください。

!

「アクセスできるユーザー」を「全員」にしないでください。 社外の人がURLを知っただけで、お客様の相談内容を見られる状態になります。

必ず「組織内の全員」（会社のGoogle Workspaceドメイン）を選んでください。

i

「次のユーザーとして実行：自分」で合っています。 こうすると、スタッフ一人ひとりにスプレッドシートを共有しなくても画面が使えます。 社内アカウント同士なので、誰がアクセスしているかはシステム側で判別できます （＝権限の出し分けが効きます）。次のステップで実際に確認します。

13

本人が正しく判別されるかテストする ── ここが最重要

権限の出し分けは「アクセスした人が誰か」をシステムが読み取れることが前提です。 ここだけは必ず実機で確かめてください。

  1. 控えたURLを自分のブラウザで開き、画面が表示されることを確認します。
  2. 自分以外の社員1名に、同じURLを開いてもらいます。
  3. その人の画面で、店舗・スタッフ管理 タブが見えているか確認します。
!

この時点ではまだ誰もスタッフマスタに登録されていないため、 全員に管理タブが見えるのが正常です（締め出しを防ぐ仕組み）。

ステップ15で権限を登録したあと、もう一度この確認をしてください。 登録後も一般スタッフに管理タブが見えたままなら、本人の判別ができていません。 その場合は下の「困ったときは」を参照してください。

✓ここまでで確認できること

  • URLを開くとダッシュボードが表示される（データはまだ0件）
  • 自分以外の社員も同じURLで開ける
  • URLの共有範囲が「組織内の全員」になっている

E. 使い始める

約10分
14

店舗マスタを実態に合わせる

初期状態では10店舗が入っています。ウェブアプリの 店舗・スタッフ管理 タブから調整してください。

  • 店舗名を変える — 編集。過去データの表記も一緒に変わります。
  • 使わない店舗 — 無効化。画面から消えますが、データは残ります。
  • 店舗を足す — 店舗を追加。店番（営業所コード）と店舗名を入力します。
i

CSVに知らない営業所コードが入っていた場合は、取り込み時に 未設定(コード) という仮の名前で自動的に店舗が作られます。 あとからここで正式名称に直せるので、事前に全部そろえる必要はありません。

15

権限を登録する ── 運用開始前に必ず

店舗・スタッフ管理 → スタッフを追加 から、 所長・チーフ・マスタ管理者を登録します。

権限レベルできること誰に
一般自分の店舗だけ閲覧・入力店舗スタッフ
管理者全店舗を閲覧＋分析レポートの保存所長・チーフ
マスタ管理上記＋CSV取込＋店舗/スタッフ管理本部・システム担当

入力するのは、所属店舗・社員番号・社員名・Googleアカウント・権限レベルです。

!

Googleアカウント欄には、その人が実際にログインに使うアドレスを正確に入力してください。 ここが本人確認の唯一の手がかりです。1文字でも違うと、その人は「未登録ユーザー」として扱われ、 全店舗が見える状態になってしまいます。

登録が終わったら、ステップ13の確認をもう一度行ってください。 一般スタッフの画面から管理タブとCSVボタンが消えていれば成功です。

i

一般スタッフは手動登録しなくて大丈夫です。 CSVを取り込むと、その中の社員が自動的に「一般」権限で登録されます。 事前に登録が必要なのは、所長・チーフ・マスタ管理者だけです。

16

CSVを取り込んでみる

マスタ管理権限のアカウントでウェブアプリを開き、 リセールリスト タブ → 右上の緑のボタン CSVインポート を押します。

  1. 営業日報から出したファイルを選ぶ（CSV・タブ区切り・Excelブック(.xls/.xlsx) のいずれでも可。文字コードは UTF-8・Shift_JIS どちらでも構いません）
  2. 取り込む を押す
  3. 取込件数・重複スキップ数・自動登録された店舗やスタッフが表示される
i

Excelブック（.xls / .xlsx）を取り込む場合は、一度だけ設定が必要です。 Apps Scriptを開き、左側メニューの サービス の ＋ を押して、 一覧から Drive API を選び 追加 してください。 これで、取り込み時に自動でスプレッドシート形式へ変換されるようになります （変換用の一時ファイルは処理後に削除されます）。

設定しない場合は、Excelで 名前を付けて保存 → ファイルの種類 CSV UTF-8（コンマ区切り） で保存し直したファイルをお使いください。

取り込むのは、ファイルの中の次の12列だけです。他の列が入っていても、列の順番が違っても構いません。

i

対象年月日 / 営業所コード / 社員番号 / 社員名 / 未成約理由(大) / 都市コード / 種別 / 出発年月 / 旅行目的(小) / 接客方法 / HIS利用歴 / 詳細

毎日同じCSVを重ねて取り込んでも安全です。 対象年月日・営業所コード・社員番号・都市コード・出発年月がすべて一致する行は 重複としてスキップされ、新しい行だけが積み上がります。

17

URLを配る

ステップ12で控えたURLを、各店舗に共有します。伝えるとよいことは3つです。

  • ブックマークして毎日開くこと（スマホのホーム画面に追加してもOK）
  • 会社のGoogleアカウントでログインすること（個人のgmailでは自分の店舗が判別できません）
  • 入力するのは リセール・STS・成約PAX・ACT日・ACT内容・メモ の6項目だけ、ということ
18

毎日の運用の流れ

いつ誰が何を
毎朝マスタ管理者前日分のCSVを取り込む
随時店舗スタッフリセールリストでフォロー状況を入力する
週次所長・チーフダッシュボードでリセール継続率を確認する
月次所長・チーフGeminiで傾向を分析し、レポートを保存する
i

🔔 長期未対応アラートは、最後に入力してから7日たってもSTSが空欄の案件に付きます。 スタッフが何か入力するたびに日付が更新されるので、こまめに触るほどアラートは正確になります。

✓導入完了。ここまでで確認できること

  • CSVを取り込むとリセールリストに案件が並ぶ
  • ダッシュボードにリセール継続率とグラフが出る
  • 一般スタッフでログインすると自分の店舗だけが見え、管理タブが消えている
  • 所長でログインすると全店舗が見え、管理タブは出ない

付録1. Geminiで傾向を分析する

＋

ダッシュボードから分析して、結果を全員に共有する

APIキーなどの準備は不要です。会社で使っているGeminiをそのまま使います。

  1. 店舗・月で絞り込む（絞り込まなければ全店舗が対象になります）
  2. Geminiで分析する を押す
  3. サマリをコピー を押す
  4. Geminiを開く からGeminiを開き、貼り付けて送信する
  5. 返ってきた所見をコピーし、同じ画面の下部に貼り付けて この画面に保存する

保存すると、ダッシュボード上部の AI分析レポート に表示され、他のメンバーも同じ所見を読めます。 日時・作成者・対象範囲も一緒に記録されます。

i

1店舗だけに絞ると、店舗単位の分析に切り替わります。 社員別の内訳が付き、Geminiへの質問も「この店舗の課題は何か」という内容に変わります。

サマリに含まれるのは集計した数値と社員名だけで、お客様のお名前や相談内容は入りません。

!

保存した分析レポートのうち、全店舗を対象にしたものは一般スタッフには表示されません （他店舗の数字が本文に含まれるため）。店舗スタッフにも読ませたい所見は、 その店舗に絞り込んでから保存してください。

＋

スプレッドシート上でGeminiに聞く（もう一つの方法）

スプレッドシートのメニュー ② AI分析用サマリを作成／更新（Gemini用） を実行すると、 AI分析用サマリ というシートができます。

店舗別・期別・未成約理由別・都市コード別・接客方法別・旅行目的別・社員別の集計が 1枚の表にまとまるので、このシートを開いた状態でサイドパネルのGeminiに質問できます。

質問例：「リセール継続率が低い店舗はどこ？全体平均とどれくらい差がある？」

付録2. コードを更新するとき

＋

修正版を反映する手順

  1. Apps Scriptを開き、該当ファイルの中身を全部消して新しい内容を貼り付ける
  2. 保存する
  3. デプロイ → デプロイを管理 → 鉛筆アイコン → バージョンを 新バージョン にして デプロイ
!

「新しいデプロイ」ではなく「デプロイを管理」から更新してください。 新しいデプロイを作るとURLが変わってしまい、配布済みのURLでは古い画面が表示され続けます。

困ったときは

権限を登録したのに、一般スタッフに管理タブが見えたままになる

本人の判別ができていません。次の順に確認してください。

1. Googleアカウントの綴り。スタッフマスタに登録したアドレスと、その人が実際にログインしているアドレスが完全に一致しているか。大文字小文字は区別しませんが、ドットやハイフンの違いは別人扱いになります。

2. 「有効」列。チェックが外れていると未登録扱いになります。

3. 公開設定。デプロイを管理 で「アクセスできるユーザー」が組織内の全員になっているか。「全員」になっていると、社外扱いとなり本人を判別できません。

4. アカウントの所属。その人が、システムを作ったアカウントと同じ会社ドメインか。別ドメインだと判別できません。

URLを開くと画面が真っ白／読み込みが終わらない

HTMLファイルの名前が違っている可能性が高いです。Index と Javascript の綴りを確認してください（JavaScript は誤り）。

名前を直したら、必ず デプロイを管理 から新バージョンとして再デプロイしてください。保存しただけでは公開中の画面は変わりません。

「店舗マスタ シートが見つかりません」と出る

フェーズC（ステップ09〜11）の初期セットアップがまだ実行されていません。データを入れるシートが1枚も作られていない状態です。

直し方は2通りあり、どちらでも同じです。

1. 画面から直す。ウェブアプリの上部に 初期セットアップを実行する という黄色いボタンが出ているので、それを押します。数十秒で完了し、そのまま使えるようになります（マスタ管理権限のアカウントのみ表示されます）。

2. スプレッドシートから直す。元のスプレッドシートを開き、メニューバーの 46期未成約ダッシュボード → ① 全シートを初期化（InitSheet） を実行します。初回は権限の承認画面が出ます（ステップ10を参照）。

メニュー自体が出ていない場合は、Apps Scriptの保存が済んでいない可能性があります。保存してからスプレッドシートを再読み込み（F5）してください。

社員番号や店番の先頭の「0」が消えてしまう

スプレッドシートは「046」「01234」のような数字を、そのままだと数値（46・1234）として保存するため、先頭の0が失われます。

本システムでは、営業所コード・社員番号・月・対象年月日・出発年月の各列を文字列として保持する書式に設定しているため、通常は起きません。

過去に取り込んだデータで桁が落ちている場合は、メニューの ① 全シートを初期化 を実行してください。桁落ちした値が正しい桁数に書き戻されます（データは消えません）。

なお、同じ人が個人別サマリで2人に分かれてしまっている場合は、管理タブの 重複した行を削除する もあわせて実行してください。

「このファイルはExcelのブック形式です」と出て取り込めない

.xls / .xlsx はそのまま取り込めますが、そのためには Drive API の追加が必要です（一度だけの設定）。このメッセージは、その設定がまだ済んでいないときに出ます。

直し方。Apps Scriptを開き、左側メニューの サービス の ＋ を押して、一覧から Drive API を選び 追加 してください。追加したらウェブアプリを開き直せば取り込めます。

設定できない場合。Excelでそのファイルを開き、ファイル → 名前を付けて保存 → ファイルの種類 CSV UTF-8（コンマ区切り）(*.csv) で保存し直し、その .csv を取り込んでください。「一部の機能が失われる可能性があります」と出ますが はい で構いません。

CSVを取り込もうとすると「ヘッダー行が見つかりません」と出る

ファイルの中に「対象年月日」という見出しの列が見つからないときに出ます。エラーの下に、実際に読み取れた1行目が表示されるので、それが見出し行かどうかを確認してください。

見出し行より上に集計行やタイトル行があっても自動で読み飛ばします。見出しの前後に空白が入っていたり、左端に連番の列が付いていても検出できます。

それでも出る場合は、見出しそのものの表記が違う（例：「対象日」）可能性が高いので、営業日報の出力設定を確認してください。

スタッフを追加するとき、所属店舗のプルダウンが空で選べない

店舗マスタの読み込みが終わる前にフォームを開くと、一瞬この状態になることがあります。プルダウンの下に「店舗マスタを読み込んでいます…」と出ている間に読み込みが終わり、自動で選択肢が並びます。

「選択できる店舗がありません」と出る場合は、店舗マスタに有効な店舗が1件も無い状態です。同じ画面の 店舗を追加 から先に店舗を登録するか、営業日報のCSVを取り込んでください（CSVに出てくる営業所コードは自動で店舗登録されます）。

CSVインポートのボタンが見当たらない

CSVインポートはマスタ管理権限だけの機能です。所長・チーフ（管理者権限）には表示されません。

取り込みを担当する方の権限レベルを「マスタ管理」に変更してください。

古いデータが画面から消えた

仕様です。リセールリスト・個人別サマリーとも直近2年（4半期）分だけを表示します。期が進むと、古い半期は自動的に表示対象から外れます。

スプレッドシート上のデータは削除されていません。各店舗シートを直接開けば過去のデータは残っています。

成約PAXに「3名」と入れたら保存できなかった

成約PAXは半角数字だけを受け付けます。集計の合計に使う列のため、文字が混ざると合計から外れて人数が少なく見えてしまうからです。

3 のように数字だけを入力してください。

マスタ管理者が自分の権限を下げてしまい、管理画面に入れなくなった

自分で自分を戻すことはできません。次のどちらかで復旧します。

方法1：他のマスタ管理者に、権限レベルを戻してもらう。

方法2：スプレッドシートを直接開き、スタッフマスタ シートの「権限レベル」列を マスタ管理 に書き換える。

こうならないよう、マスタ管理者は2名以上登録しておくことをおすすめします。

店舗を削除しようとしたら「データが残っているため削除できません」と出る

誤ってデータごと消してしまわないための安全装置です。

閉店・休止した店舗は削除ではなく「無効化」を使ってください。画面やフィルタから消えますが、データは保持されます。
