# 日報管理システム (GAS)

営業日報の入力・集計・編集を行う Google Apps Script Web アプリです。3つの画面から構成されます。

| URL | ページ | 用途 |
|---|---|---|
| `?page=`（未指定） | `index.html` | 日報入力フォーム |
| `?page=dashboard` | `dashboard.html` | 営業ダッシュボード（KPI・グラフ・編集/削除） |
| `?page=admin` | `admin.html` | 管理者メニュー（集計・トリガー設定） |

## 今回のコードレビューで見つかった不具合・修正内容

### 🔴 重大（セキュリティ）
1. **空メールが admin 扱いになるバグ**（`_getUserAuth`）
   `Session.getActiveUser().getEmail()` が空文字を返すケース（デプロイ設定や
   ドメイン外アクセス等）で、無条件に `role = 'admin'` を付与していました。
   削除権限まで含む管理者権限が誰にでも渡ってしまう重大な権限バグです。
   → 空メールは必ず `unknown`（権限なし）になるよう修正しました。

2. **権限に関わらず全社の生データがブラウザに送信されていた**（`getRawDataForDashboard`）
   店舗スタッフはもちろん、「設定」シートに登録されていない未許可のユーザーでも、
   ダッシュボードを開くと全店舗・全件の生データ（チャレンジNO・顧客関連情報等）が
   そのままブラウザに届いていました（画面上は自店舗のみに絞って表示されるため
   気づきにくいですが、開発者ツールで丸見えの状態でした）。
   → キャッシュはこれまで通り全社データを保持しつつ、**クライアントに返す直前に
   サーバー側で役割・店舗に応じて絞り込む**よう修正しました。`unknown` ロールには
   空データを返します。

### 🟠 バグ
3. `submitDailyReport` で例外発生時に `LockService` のロックが解放されないパスが
   存在（`try/finally` で確実に解放するよう修正）。
4. `index.html`: 区分を「新規」→「既存」に切り替えても、非表示にした「問合せ方法」
   「媒体」の入力値が保持されたまま送信されてしまう不具合（非表示時に値をクリア
   するよう修正）。
5. `dashboard.html`: 成約判定が `row[11] === '成約'` のように前後空白を考慮しない
   箇所と、バックエンド側の `.trim()` 済み比較が混在しており、値に空白が入ると
   集計がずれる可能性がありました（`isContract()` ヘルパーに統一）。
6. `admin.html`: `getAdminMenuData()` の呼び出しに `withFailureHandler` が無く、
   バックエンド側でエラーが起きると「データを確認中...」から進まなくなる不具合。
7. **`admin.html` が実質使用不可能だった**: `doGet` に `page=admin` のルーティングが
   存在せず、かつ `getAdminMenuData` / `runBuildSummary` / `setupMonthlyTrigger` /
   `runArchive` はどれも `Code.gs` に実装されていませんでした。今回ルーティングを
   追加し、`runArchive` を除く3つを実装しています。
   - `runArchive` のみ**未実装のままにしています**。`admin.html` の文言は
     「単一のDATAシートから前年度データをPREV_YEARへ移動して削除する」設計を
     前提としていますが、実際のコードは `getCurrentYearSheet()` によって
     年ごとに `DATA_2025` / `DATA_2026` ... と自動でシートが分かれる設計になっており、
     両者は矛盾します。誤って実装すると年度別データを壊す恐れがあるため、
     データを一切変更しない説明メッセージを返すだけの安全な実装に留めています。
     本当に「アーカイブ」機能が必要な場合は、まず現行の年度別シート設計をどう
     扱うか（本当に必要か）を確認してから実装することを推奨します。

### 🟡 非効率・改善
8. チャレンジNO重複チェックが毎回シート全列を読み込んでいたのを、該当列のみ
   取得するよう変更（`isChallengeDuplicate_`、`submitDailyReport` / `updateRow` で共通化）。
9. チャレンジNOのフォーマット検証がフロントエンドのみだったため、サーバー側にも
   同じ正規表現チェックを追加（直接API呼び出しでの不正値登録を防止）。
10. 日報入力フォーム: 送信成功後に毎回「店舗名」「担当者」を再入力する必要があった
    UXを改善し、この2項目のみ値を保持するようにしました。
11. ダッシュボードの編集モーダルが自由入力の `<input type="text">` だったため、
    マスタと表記が揺れる／入力ミスが起きやすい状態でした。入力フォームと同じ
    マスタデータ（店舗・問合せ方法・媒体・方面・式場・問合結果・AGT・プラン）を
    使ったプルダウンに変更し、方面→式場の連動も対応しました。
12. 削除確認が素の `confirm()` で、編集モーダルが一瞬表示されてからダイアログが
    出る、キャンセルすると編集モーダルが開いたまま残る、というUXの粗さがあったため、
    専用の確認ダイアログに置き換えました。
13. 元ファイルには Markdown のコードフェンス記号（\`\`\`）が `<style>` やHTML本文の
    中にそのまま紛れ込んでおり、該当するCSSルールが無効になっていました
    （今回の全面リライトで解消済み）。

## UI刷新について

元のダッシュボードはダーク＋グラスモーフィズム調でしたが、依頼いただいた
Salesforce風の参考画像に寄せて、**ライトテーマ・カード基調**のデザインに
3画面とも統一しました。主な変更点:

- 白背景＋ブルー基調のカードUI、角丸・柔らかい影で情報をグルーピング
- 成約率(CVR)カードをスピードメーター風のゲージチャートに変更（参考画像の
  「Team Quota Attainment」ゲージを意識）
- KPIカード・タブ・テーブル・バッジを共通のデザイントークンで統一
- 日報入力フォームをセクション分け（基本情報／挙式・旅行情報／結果）して視認性を向上
- 管理者メニューへの導線をダッシュボードのヘッダーに追加（管理者のみ表示）

## 未確認・要相談事項

- `runArchive`（年度末アーカイブ）は上記の理由で未実装です。本当に必要かどうか
  含めて仕様を確認のうえ、実装するかどうかご判断ください。
- KPI設定シートで `total` / `contracts` / `cvr` 以外の独自KPI ID を追加しても、
  フロントエンド側は数値を算出できず「-」のまま表示されます（元の設計から
  変わらない既知の制限です）。カスタムKPIを追加したい場合は集計ロジックの
  追加実装が必要です。
