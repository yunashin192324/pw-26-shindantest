# PhotoWED 支店ポータル（全支店横断WEBアプリ版）セットアップ手順

`ROW_fixed.gs`（ROW支店専用スクリプト）を、世界中の支店（ウィーン支店・イスタンブール支店…）へ
**コードを一切書き換えずに**横展開できるように再設計したものです。

## これまでとの違い

| 項目 | 旧（ROW_fixed.gs） | 新（このフォルダ） |
|---|---|---|
| 展開方法 | 支店ごとにスプレッドシート＋スクリプトをコピー | 1つのWebアプリを全支店で共有 |
| 支店固有情報 | `BRANCH_CODE` 等をコードに直書き | 「支店マスタ」シートに1行追加するだけ |
| アクセス制御 | スプレッドシートの共有権限のみ | ログイン（支店コード＋パスコード）で自分の支店のデータのみ表示 |
| 日本側の閲覧範囲 | 送信先メールのみ | HQでログインすると全支店を横断閲覧・操作可能 |
| UI | Googleスプレッドシート本体を直接編集 | スマホ対応のWebアプリ画面 |
| 支店追加コスト | コード変更＋新規デプロイが必要 | 支店マスタへ1行追加するだけ（コード変更・再デプロイ不要） |

## ファイル構成

- `appsscript.json` — マニフェスト（Webアプリとして "全員アクセス可" で公開する設定）
- `Code.gs` — サーバーサイドロジック（認証・データ操作・メール通知・アラート）
- `Index.html` / `Stylesheet.html` / `JavaScript.html` — スマホ対応のフロントエンド（1画面SPA）
- 本ファイル — セットアップ手順

## デプロイ手順

1. Googleスプレッドシートを新規作成する（既存の「予約一覧」シート等をそのまま移行したい場合は既存シートでも可）。
2. スプレッドシートのURLからスプレッドシートIDを控える（`.../d/【ここ】/edit`）。
3. スプレッドシートの拡張機能 → Apps Script を開く。
4. デフォルトの `コード.gs` を削除し、このフォルダの5ファイル（`appsscript.json`, `Code.gs`, `Index.html`, `Stylesheet.html`, `JavaScript.html`）の中身をそのまま同名で作成・貼り付ける。
   - `appsscript.json` はエディタの「プロジェクトの設定」→「"appsscript.json" マニフェスト ファイルをエディタで表示する」を有効にすると編集できます。
5. `Code.gs` 冒頭の `SPREADSHEET_ID` に手順2で控えたIDを設定する。
6. Apps Scriptエディタの関数選択で `setupPortal` を選び、実行する（初回のみ）。
   - 「支店マスタ」「予約一覧」「やり取り履歴」「過去一覧」の4シートと、サンプル支店行（HQ / ROW / VIE / IST）が自動作成されます。
7. 「支店マスタ」シートを開き、各行の **ログインパスコード** と **通知先メール** を実際の値に書き換える。
   - 支店を追加したい場合はここに1行足すだけです（例：`BKK` / バンコク支店 / `BRANCH` / 合言葉 / bangkok-branch@his-world.com / TRUE）。コードの変更・再デプロイは不要です。
8. Apps Scriptエディタ右上の「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選択。
   - 実行するユーザー：自分（あなた）
   - アクセスできるユーザー：全員
9. 発行されたWebアプリのURLを、各支店・HQの担当者に配布する（このURLがそのままログイン画面になります）。
10. 関数選択で `setupTriggers` を実行し、日次のアラート・アーカイブ処理のトリガーを設定する。

## 既存データ（旧ROW_fixed.gsの「予約一覧」）の移行について

旧シートは列名が `STS JPNROM` / `STS ROMJPN` のように支店名（ROM）を含む形になっています。
新シートは全支店共通にするため、列名を以下のように読み替えています。

- `STS JPNROM` → `STS HQ`（日本手配課が入力するステータス）
- `STS ROMJPN` → `STS 支店`（支店側が入力するステータス）
- `MSG JPNROM` → `MSG HQ`
- `MSG ROMJPN` → `MSG 支店`
- 先頭に `支店コード` 列を追加（例：`ROW`）

移行スクリプトが必要な場合（既存データを一括で新形式にコピーしたい場合）は別途対応可能です。まずはこの構成で問題ないかご確認ください。

## 権限まわりの設計メモ

- ログインはOAuthではなく「支店コード＋支店マスタに登録したパスコード」による簡易認証です。海外拠点にGoogle Workspaceアカウントを配布していない前提に合わせています。
- セッションは `CacheService` に保存され、最大6時間で失効します（操作するたびに自動延長）。
- 支店ロールのユーザーは、自分の `支店コード` と一致する予約行のみ閲覧・操作できます（サーバー側 `assertRowVisible_` で強制）。
- HQロールのユーザーは全支店を閲覧・操作でき、さらに「支店管理」画面から支店の追加・編集ができます。
