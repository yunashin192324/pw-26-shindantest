# PhotoWED 支店ポータル（全支店横断WEBアプリ版）セットアップ手順

`ROW_fixed.gs`（ROW支店専用スクリプト）を、世界中の支店へ**コードを一切書き換えずに**横展開できるように
再設計したものです。関東手配課・関西手配課どちらでログインしても全支店を横断閲覧・操作でき、
支店ユーザーは自分の支店のデータのみアクセスできます。

## ファイル構成

- `appsscript.json` — マニフェスト（Webアプリとして "全員アクセス可" で公開する設定）
- `Code.gs` — サーバーサイドロジック（認証・データ操作・検索・メール通知・アラート）
- `Index.html` / `Stylesheet.html` / `JavaScript.html` — スマホ対応のフロントエンド（1画面SPA）
- 本ファイル — セットアップ手順・設計メモ

## デプロイ手順

1. Googleスプレッドシートを新規作成する（IDを控えておく：`.../d/【ここ】/edit`）。
2. 拡張機能 → Apps Script を開き、このフォルダの5ファイルの中身を同名で作成・貼り付ける。
3. `Code.gs` 冒頭の `SPREADSHEET_ID` に手順1のIDを設定する。
4. 関数選択で `setupPortal` を実行する（初回のみ）。
   - 「支店マスタ」「プランマスタ」「オプションマスタ」「予約一覧」「やり取り履歴」「過去一覧」
     「ステータス変更履歴」の7シートと、24支店＋関東/関西手配課アカウントのサンプル行が自動作成されます。
5. 「支店マスタ」シートで各行の **ログインパスコード** と **通知先メール** を実際の値に書き換える。
6. 「プランマスタ」「オプションマスタ」シートに、支店ごとのプラン名・オプション名を入力する
   （書式は下記「マスタ管理について」を参照）。
7. 「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」
   （実行するユーザー：**アクセスしたユーザー** ／アクセスできるユーザー：**組織内（his-world.com）の全員**）。
   ※この設定は「誰が変更・送信したか個人名を記録する」ために必須です。詳しくは下記
   「13. メッセージ・変更履歴に個人名を記録」を参照してください。
8. 発行されたURLを各支店・関東手配課・関西手配課の担当者に配布する（そのままログイン画面になります）。
9. 関数選択で `setupTriggers` を実行し、日次のアラート・アーカイブ処理のトリガーを設定する。

## マスタ管理について（支店・プラン・オプション）

支店・プラン・オプションの登録／編集は、**アプリの画面ではなく裏のスプレッドシートを直接編集する**運用です。

- **支店マスタ**：支店を追加する場合は1行追加するだけ（コード変更・再デプロイ不要）。列の意味は本ファイル末尾の表を参照。
- **プランマスタ／オプションマスタ**：`支店コード / 名称 / 有効` の3列。支店ごとに複数行登録できます。
  ここに登録した内容が、案件詳細画面の「プラン名」「オプション」欄の選択肢としてそのまま反映されます
  （画面側は読み取り専用のプルダウンです）。

なお `Code.gs` にはこれらのマスタを書き込むAPI（`apiSaveBranch` / `apiSetBranchActive` /
`apiSavePlanItem` / `apiSaveOptionItem`）も残してあります。今後アプリ内に管理画面を作りたくなった場合は
そのまま利用できます。

## 今回追加・変更した仕様

### 1. 日本側は「関東手配課」「関西手配課」の2アカウントに分離
- ロールは `BRANCH`（支店）と `JP`（日本側）の2種類。関東・関西どちらでログインしても**権限は同じ**で、
  全支店を横断して閲覧・操作できます。
- 案件一覧・検索画面の「表示範囲」チェックボックスで、全国／関東手配課／関西手配課／支店ごとを
  自由に組み合わせて絞り込めます（複数選択可）。
- ログイン画面はプルダウン選択式です（コードを覚えて入力する必要はありません）。
- **メッセージの宛先は、ログインしている拠点ではなく「開いている案件の支店」で決まります。**
  例：関東手配課でログインしてローマの案件を開き、メッセージを送信すると、宛先はローマ支店の
  通知先メール（支店マスタに登録済み）になります。関東／関西の違いは、日本側からのメッセージが
  どちらのチームの担当分として履歴に残るかだけです。

### 2. ステータス（STS）：コードと編集ルール
`RQ` / `OK` / `CHK` / `CR` / `FN` / `CW` / `NC` / `UC` / `CF` の9種類をそのまま選択式で使います
（和訳ラベルは表示しません）。**日本側と支店側は互いの相手のステータスを直接編集できません。**

コードの意味（運用ヒアリングに基づく）：
- `RQ`＝予約依頼、`CHK`＝空き確認のみ、`NC`＝依頼なし／状態リセット
- `UC`＝現地に空きがない（`RQ`・`CHK`に対する支店側の回答）
- `CR`＝日本側が既存予約のキャンセルを依頼（キャンセルリクエスト）
- `CW`＝キャンセル成立・チャージなし、`CF`＝キャンセル成立・キャンセルチャージあり（`CR`に対する支店側の回答）
- `OK`＝空きあり、`FN`＝最終確定 — 運用上の到達状態

編集ルール：
- **STS(JP側)** は日本側のみが編集できます。いつでも自由に値を選べます。
- **STS(支店側)** は支店側のみが編集できます。ただし対になる **STS(JP側) の現在値**によって
  選べる範囲が変わります。
  - STS(JP側) が `NC`・`RQ`・`CHK` のとき → 支店側は自由にどのコードでも選べます（空きがなければ`UC`など）。
  - STS(JP側) が `CR` のとき → 支店側は `CW`（チャージなし）か `CF`（チャージあり）のみ選べます。
  - それ以外（`OK`・`FN`・`CW`・`UC`・`CF`・未設定）のとき → 支店側は変更できません（ロック）。
- このルールはメインのSTSだけでなく、**OP1〜OP5のオプションごとのSTS(JP側)／STS(支店側)にも
  同じように適用**されます（オプションごとに独立してゲートされます）。

### 3. 予約済み案件内の変更は「保存のみ／メッセージのみ送信／変更＋メッセージ送信」の3択で確定
既存予約内のほぼ全ての項目（ステータス・オプション・撮影日・挙式日・ホテル・プラン・共有メモ…
DriveフォルダURLを除く全て）は、その場で自動保存せず、画面下部の3つのボタンのいずれかで確定します。

- **保存のみ（通知しない）**：入力中の変更を保存するだけで、相手への通知（履歴ログ・メール）は発生しません。
  共有メモの更新など、相手に知らせる必要がない変更に使います。
- **メッセージのみ送信**：入力中の変更フィールドには触れず、メッセージだけを1件の履歴・メールとして送信します
  （変更は保存されずに残ったままなので、別途「保存のみ」か「変更＋メッセージ送信」で確定してください）。
- **変更（＋メッセージ）を決定して送信**：入力中の全ての変更内容を保存し、任意で書いたメッセージと合わせて
  1回の履歴ログ・1通のメールとして相手に通知します（例：日本側が新しいオプションを追加してSTS(JP側)を
  `RQ`にする、という一連の変更を1回の送信で支店へ通知）。

サーバー側APIは `apiSaveFieldsQuiet`（保存のみ）と `apiCommitChanges`（メッセージのみ／変更＋メッセージ、
`changes`が空ならメッセージのみとして扱う）の2つに統一しています。

### 4. 案件番号（管理番号）は支店ごとに一意なプレフィックス＋連番
- 支店マスタの「案件番号プレフィックス」列で、支店ごとに管理番号の先頭文字を設定します。
- **ローマ支店は既存運用のため `R` のまま固定**（変更しないでください）。他の支店は未使用のため、
  デフォルトで支店コードそのもの（例: `VIE` → `VIE-001`）を使う設計にしています。
- 連番はその支店の行だけを数えて採番するため、支店が何十件に増えても番号が衝突したり
  巻き戻ったりしません。プレフィックスの重複は支店保存時にサーバー側でチェックします
  （現在はマスタ書き込みAPI側のチェックのみのため、スプレッドシートを直接編集する場合は
  プレフィックスが重複しないよう手動で確認してください）。

### 5. 撮影日FIX・挙式日FIXの変更ログ
撮影日FIX・挙式日FIXも上記3択の対象です。「変更（＋メッセージ）を決定して送信」を選ぶと
「変更前 → 変更後」が履歴・メールの本文に自動で含まれます（「保存のみ」を選んだ場合は通知されません）。

### 6. プラン・オプションは支店ごとにマスタ管理
「プランマスタ」「オプションマスタ」シート（国・支店ごとに内容が異なる前提）に登録した内容が、
案件詳細の「プラン名」「オプション」欄でプルダウンとして選べます。

### 7. お名前・請求先・日本支店名
- `新郎名（ローマ字）` `新婦名（ローマ字）` の2項目で管理します。
- `請求先`（北海道／東北／関東／中部／関西／中四国／九州の7区分）を追加しました。
- `日本支店名`（案件を扱う日本側の店舗名）と `店舗／担当（現地）`（海外支店側の店舗・担当者）を
  別項目として管理します。

### 8. 案件番号・チャレンジ番号を常に表示
一覧・検索結果・詳細画面のいずれにも「管理番号」「CHG NO（チャレンジ番号）」を常時表示しています。

### 9. メッセージ・共有メモ
- やり取り履歴（メッセージ）は新しい日時が上に来る順で表示します。
- 「共有メモ」欄：支店・日本側どちらも自由に書き換えられる、送信操作を伴わないメモ欄です。

### 10. 検索機能
検索画面で以下の条件を組み合わせて検索できます（すべて任意・AND条件）。
- 管理番号（部分一致）／チャレンジ番号（部分一致）
- お名前（ローマ字・新郎新婦どちらでも部分一致）
- 国・都市（日本側ユーザーのみ表示）
- **STS(JP側)／STS(支店側)**（完全一致）
- 撮影日FIX または 挙式日FIX の期間（開始日〜終了日）
- 「過去一覧（アーカイブ済み案件）も含める」チェック
- 表示範囲チェックボックス（日本側ユーザーのみ。全国／関東／関西／支店ごと）

### 11. 一覧のキャンセル表示切り替え
案件一覧は既定で「生きている（キャンセルでない）」案件のみ表示します。
STS(JP側)またはSTS(支店側)が `CW` の案件は、「キャンセル（CW）済みも表示する」チェックを
入れたときだけ表示されます（日本側・支店側どちらの一覧にも適用）。

### 12. 過去一覧への自動移動ルールを拡張
撮影日FIXまたは挙式日FIXのいずれかが**今日より過去になった時点で**、ステータスに関わらず
自動的に「過去一覧」へ移動します（従来は「STSがFNかつ日付超過」のみが対象でしたが、
日付が過ぎたら自動的に過去扱いにする、という単純なルールに変更しました）。
`CW`（キャンセル）の案件は日付に関係なく即座に過去一覧へ移動します。
過去一覧に移動した案件も、検索・詳細閲覧・編集・メッセージ送信は引き続き可能です。

### 13. メッセージ・変更履歴に個人名を記録
支店・日本側とも、各拠点で使うGoogleアカウントは「氏名@his-world.com」形式（氏名部分がメールの
ローカル部）で運用されている前提で、`Session.getActiveUser().getEmail()` から実際の担当者名を
取得し、「氏名（支店名／チーム名）」の形でメッセージ送信者・変更者として履歴とメール本文に残します。

これを機能させるため、Webアプリのデプロイ設定を
**「実行するユーザー：アクセスしたユーザー」「アクセスできるユーザー：組織内（his-world.com）の全員」**
に変更しました（`appsscript.json` の `executeAs: USER_ACCESSING` / `access: DOMAIN`）。

- 海外支店の担当者も含めて **全員が his-world.com のGoogleアカウントでログインした状態でURLを開く**
  必要があります。もし一部の支店にhis-world.comアカウントがない場合は、個人名の記録を諦めて
  従来どおり `executeAs: USER_DEPLOYING` / `access: ANYONE`（支店コード＋パスコードのみで誰でもアクセス可）
  に戻すことも可能です。その場合は個人名は記録されず、支店名／チーム名のみが表示されます
  （`getActiveUserName_()` が空文字を返すため自動的にフォールバックします）。
- 支店コード＋パスコードのログインは、この変更後も**役割（どの支店／どのチームとして操作するか）を
  決めるためにそのまま残しています**。個人のGoogleアカウントだけでは「今どの支店として動いているか」
  は判別できないためです。

### 14. ステータス変更履歴（誰が・いつ・何を変更したか）
STS(JP側)・STS(支店側)（メイン・オプション共通）を変更すると、新設の「ステータス変更履歴」シートに
`管理番号・フィールド名・変更前・変更後・変更者・日時` が自動で記録されます。「保存のみ」で変更した
場合も記録されます（相手への通知が発生しないだけで、監査ログとしては必ず残ります）。

案件詳細画面では、各STSの値の下に「履歴」リンクがあり、タップするとそのフィールドの変更履歴
（新しい順）がその場に展開されます（`apiGetFieldHistory` で取得）。

### 15. 一覧の並び順
案件一覧は撮影日FIXが**今日に近い日付から順**に並びます（未定の案件は末尾）。

### 16. 支店側の画面でもステータス・オプションを編集できます
支店ロールでログインすると、STS(支店側)・各オプションのSTS(支店側)・オプション名は、
「2. ステータス（STS）：コードと編集ルール」に書いたゲート条件を満たしていれば選択式で編集できます。
ロックされている場合は `🔒 現在の値（STS JP: 現在のJP側の値）` という形で理由も表示されます
（以前はロック時の表示が単なる `-` で、なぜ編集できないのか分かりづらかったため改善しました）。
また、`.status-row` / `.status-card` 用のCSSが抜けていて見た目が崩れていた不具合も修正しています。

すぐに動作を確認したい場合は、STS(JP側)が `NC`・`RQ`・`CHK` のいずれかになっている案件（新規作成
直後の案件は既定でSTS(JP側)＝`RQ`です）を支店側で開いてください。

### 17. 案件一覧・検索結果に「担当（関東手配課／関西手配課）」を表示
"管轄" 列の値をもとに、一覧カード・検索結果カード・詳細画面のいずれにも「担当: 関東手配課」のように
表示するようにしました（支店側の画面でも表示されます。従来はこの情報がどこにも表示されていませんでした）。

### 18. 撮影希望場所は任意入力＋マスタ候補（datalist）
「撮影希望場所」は国・地域によって全く異なるため、プラン名のような強制の選択式にはせず、
自由入力の欄に変更しました。新設の「撮影場所マスタ」シート（プランマスタ・オプションマスタと同じ
`支店コード・名称・有効` の構成）に登録しておくと、入力欄で候補として選べます（`<input list>` +
`<datalist>`）。候補になくても自由に文字を入力して保存できます。

### 19. 請求番号（現地支店が名称を変更できる欄）
現地支店が使う「請求番号」欄を追加しました。この欄の**名称そのもの**を支店ごとに変更できるよう、
支店マスタに「請求番号欄名称」列を追加しています（例：支店によって呼び方が違う場合に対応）。
未設定の場合は既定で「請求番号」と表示されます。値の入力・変更は他の項目と同じく3択（保存のみ／
メッセージのみ送信／変更＋メッセージ送信）で確定します。

### 20. 現地記入欄（当日の運用情報）
案件詳細に「現地記入欄」タブを新設し、以下の項目を追加しました。いずれも自由入力で、
他の項目と同じ3択の保存・通知フローに従います。
- 当日の担当／ヘアメイク／カメラマン／アシスタント／配車時間／メモ（現地用）

### 21. 撮影日◯日前アラートを45日前に変更
従来40日前だった「STS未完了アラート」を **撮影日の45日前** に変更しました
（`checkAlerts` トリガー、`ALERT_DAYS_BEFORE` 定数）。

### 22. 納品期限アラート（新設）
撮影日から一定日数が過ぎてもDriveフォルダURL（納品）が未登録の案件を、日本側（管轄の手配課）へ
メールで通知する `checkDeliveryAlerts` を新設し、`checkAlerts` と同様に毎日8時に実行するトリガーを
`setupTriggers()` に追加しました。日数（何日で通知するか）は**国・支店ごとに異なる**という要件のため、
支店マスタの「納品期限日数」列で支店ごとに設定できます（未設定の場合は既定30日 `DELIVERY_ALERT_DEFAULT_DAYS`
にフォールバック）。ちょうど期限日数に達した日に1回だけ通知します（毎日重複して届かないようにするため）。

### 23. 案件詳細をタブ構成に変更
1件の画面が縦に長くなりすぎていたため、案件詳細を「メッセージ」「予約内容」「現地記入欄」の
3タブに分割しました。開いたときは最初に「メッセージ」タブが表示されます（未読の有無にまず気づける
ように）。画面下部の「保存のみ／メッセージのみ送信／変更（＋メッセージ）を決定して送信」の3ボタンは
「メッセージ」タブにありますが、対象になるのは**どのタブで入力した変更でも全て**（予約内容タブ・
現地記入欄タブの入力を含む）です。タブを切り替えても入力中の内容（保留中の変更）は保持されます。

### 24. 日本側専用の統計ダッシュボード（新設）
ナビゲーションに日本側ユーザーのみ表示される「統計」タブを追加しました（`apiGetStats`）。
集計対象は**現在進行中（＝過去一覧に移っておらず、STS(JP側)・STS(支店側)ともにCW＝キャンセル成立でない）**
案件のみです（「あと何件残っているか」を知りたい、という要望のため）。
- **現在進行中の件数**（メイン表示）
- **累計件数**（過去一覧＝アーカイブ済み・キャンセル済みも含めた全期間の合計。参考値として併記）
- ステータス別件数（RQ／OK／FN。現在進行中のみが対象。STS(JP側)・STS(支店側)のいずれかがそのコードであれば集計）
- 月別件数（現在進行中のみ、撮影日FIX基準、未定は「未定」として集計）
- 国別件数（現在進行中のみ）
- 日本側店舗（"日本支店名"）別件数（現在進行中のみ）

案件一覧と同じ「表示範囲」チェックボックス（全国／関東手配課／関西手配課／支店ごと）で絞り込めます。

### 25. メッセージ送信欄に自分の実名を表示
「13. メッセージ・変更履歴に個人名を記録」で送信者・変更者として記録される実名を、履歴の中だけでなく
「メッセージ」タブの送信ボタンの上にも「送信者として記録されます：氏名（支店名／チーム名）」という形で
表示するようにしました。送信前に「誰の名前で送られるか」がその場でわかります。

### 26. メッセージの既読チェックに「誰が・いつ」を記録
やり取り履歴のJP確認／支店確認チェックボックスは、従来はON/OFFと日時のみでしたが、
**チェックした人の実名**も記録するようにしました（やり取り履歴シートに「CHECK JP 氏名」
「CHECK 支店 氏名」列を追加）。履歴の表示も「JP確認済み：氏名（日時）」のように変わり、
未確認の場合は「JP未確認」と表示されます。

### 27. 要対応（未読）の案件を一覧の上に色つきで表示
相手側（自分が支店なら日本側、自分が日本側なら支店側）から来たメッセージ・変更のうち、
自分側でまだ確認（チェック）していないものがある案件は、案件一覧の**最上位**に、
背景色を変えた状態（オレンジ系のハイライト＋「● 要対応」チップ）で表示されます。
やり取り履歴の該当メッセージにチェックを入れる（既読にする）と、次に一覧を開いたときには
通常の並び順（撮影日が近い順）に戻ります。この判定は、やり取り履歴に新設した「送信者ロール」列
（JPまたはBRANCH）と、既存のCHECK JP／CHECK 支店の状態を組み合わせて行っています。

## 支店マスタの列構成

| 列 | 説明 |
|---|---|
| 支店コード | ログインID。JPロールの場合は `KANTO` / `KANSAI` のような任意のコードでも可 |
| 支店名 | 画面表示名（例: ウィーン支店、関東手配課） |
| 国 / 都市 | 検索・一覧表示に使用（支店ロールのみ設定） |
| ロール | `BRANCH` または `JP` |
| 手配チーム | JPロールのみ。`関東` または `関西`（"管轄"列の値と一致させる） |
| ログインパスコード | ログイン時の合言葉 |
| 通知先メール | メール通知の宛先（カンマ区切りで複数可） |
| 案件番号プレフィックス | BRANCHロールのみ。管理番号の先頭（支店ごとに一意、ローマ支店は`R`固定） |
| 請求番号欄名称 | BRANCHロールのみ。案件詳細の「請求番号」欄の表示名を支店ごとに変更（未設定なら「請求番号」） |
| 納品期限日数 | BRANCHロールのみ。撮影日から何日でDriveフォルダURL未登録アラートを送るか（未設定なら既定30日） |
| 有効 | falseにするとログイン不可・ログイン選択肢にも出ない |
