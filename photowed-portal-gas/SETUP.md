# PhotoWED 支店ポータル（全支店横断WEBアプリ版）セットアップ手順

`ROW_fixed.gs`（ROW支店専用スクリプト）を、世界中の支店へ**コードを一切書き換えずに**横展開できるように
再設計したものです。関東手配課・関西手配課どちらでログインしても全支店を横断閲覧・操作でき、
支店ユーザーは自分の支店のデータのみアクセスできます。

## ファイル構成

- `appsscript.json` — マニフェスト（Webアプリとして "全員アクセス可" で公開する設定）
- `Code.gs` — サーバーサイドロジック（認証・データ操作・検索・メール通知・アラート）
- `Index.html` / `Stylesheet.html` / `JavaScript.html` — スマホ対応のフロントエンド（1画面SPA）
- 本ファイル — セットアップ手順・設計メモ

## デプロイ手順

1. Googleスプレッドシートを新規作成する（IDを控えておく：`.../d/【ここ】/edit`）。
2. 拡張機能 → Apps Script を開き、このフォルダの5ファイルの中身を同名で作成・貼り付ける。
3. `Code.gs` 冒頭の `SPREADSHEET_ID` に手順1のIDを設定する。
4. 関数選択で `setupPortal` を実行する（初回のみ）。
   - 「支店マスタ」「プランマスタ」「オプションマスタ」「予約一覧」「やり取り履歴」「過去一覧」の
     6シートと、24支店＋関東/関西手配課アカウントのサンプル行が自動作成されます。
5. 「支店マスタ」シートで各行の **ログインパスコード** と **通知先メール** を実際の値に書き換える。
6. 「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」（実行するユーザー：自分／アクセス：全員）。
7. 発行されたURLを各支店・関東手配課・関西手配課の担当者に配布する（そのままログイン画面になります）。
8. 関数選択で `setupTriggers` を実行し、日次のアラート・アーカイブ処理のトリガーを設定する。

## 今回追加・変更した仕様

### 1. 日本側は「関東手配課」「関西手配課」の2アカウントに分離
- ロールは `BRANCH`（支店）と `JP`（日本側）の2種類。`JP` は支店マスタの「手配チーム」列で
  関東／関西を区別しますが、**権限は関東・関西どちらでログインしても同じ**で、全支店を横断して
  閲覧・操作できます。
- 案件一覧・検索画面の「表示範囲」チェックボックスで、**全国／関東手配課／関西手配課／支店ごと**を
  自由に組み合わせて絞り込めます（複数選択可、何も選ばない場合は全件表示）。
- サンプルのログインコードは `KANTO` / `KANSAI` です（支店マスタで変更可能）。

### 2. ステータス（STS）は和訳せずコードのまま運用
`RQ` / `OK` / `CHK` / `CR` / `FN` / `CW` / `NC` の7種類をそのまま選択式で使います。
「確定」のような和訳ラベルは表示しません。各コードの正式な意味は運用ルールとして別途チームで
定義してください（このアプリはコードの妥当性チェックのみ行います）。

### 3. 案件番号（管理番号）は支店ごとに一意なプレフィックス＋連番
- 支店マスタの「案件番号プレフィックス」列で、支店ごとに管理番号の先頭文字を設定します。
- **ローマ支店は既存運用のため `R` のまま固定**（変更しないでください）。他の支店は未使用のため、
  デフォルトで支店コードそのもの（例: `VIE` → `VIE-001`）を使う設計にしています。
- 連番は「その支店の行だけ」を数えて採番するため、支店が何十件に増えても番号が衝突したり
  巻き戻ったりしません。プレフィックスの重複は支店保存時にサーバー側でチェックします。
- アーカイブ済み（過去一覧に移動済み）の案件も採番時にカウント対象に含めているため、
  アーカイブ後に番号が再利用されて衝突することもありません。

### 4. 撮影日FIX・挙式日FIXの変更は自動でログ＋通知
「日付変更の場合どうすればよいか」への回答として、以下の挙動にしました。
- 撮影日FIX・挙式日FIXを変更すると、**自動で「変更前 → 変更後」の履歴を残し**、支店・日本側の
  両方へ通知メールを送ります。担当者が手でメッセージを書く必要はありません。
- 撮影日FIXの変更時は、従来どおり一覧が撮影日昇順に自動で並び替わります。
- 挙式日FIXは撮影日FIXとは別の日程として管理できるようにしました（撮影と挙式が別日になる
  ケースを想定）。アラート・アーカイブなどの自動処理は従来どおり撮影日FIXのみを基準にしています。

### 5. プラン・オプションは支店ごとにマスタ管理
- 「プラン・オプション管理」画面（支店ユーザーは自支店のみ、JPは支店を選んで）でプラン名・
  オプション名を登録／無効化できます。
- 案件詳細のプラン名・オプション欄は、登録したマスタが入力候補（オートコンプリート）として出ますが、
  自由入力も可能です。マスタにない値を入力してもエラーにはなりません。

### 6. お名前は新郎・新婦をローマ字で管理
`新郎名（ローマ字）` `新婦名（ローマ字）` の2項目に変更しました。海外支店・現地手配先とのやり取りを
前提に、ローマ字表記を基本とします。

### 7. 案件番号・チャレンジ番号を常に表示
一覧・検索結果・詳細画面のいずれにも「管理番号」「CHG NO（チャレンジ番号）」を常時表示しています。

### 8. メッセージ・共有メモ
- やり取り履歴（メッセージ）は**新しい日時が上に来る順**で表示します。
- 「共有メモ」欄を新設しました。支店・日本側どちらも自由に書き換えられる、送信操作を伴わない
  メモ欄です（メッセージ送信のようにメール通知や履歴ログは発生しません）。

### 9. 検索機能
検索画面で以下の条件を組み合わせて検索できます（すべて任意・AND条件）。
- 管理番号（部分一致）／チャレンジ番号（部分一致）
- お名前（ローマ字・新郎新婦どちらでも部分一致）
- 国・都市（日本側ユーザーのみ表示。支店マスタの国・都市情報を利用）
- 撮影日FIX または 挙式日FIX の期間（開始日〜終了日）
- 「過去一覧（アーカイブ済み案件）も含める」チェック
- 表示範囲チェックボックス（日本側ユーザーのみ。全国／関東／関西／支店ごと）

アーカイブ済みの案件も検索結果からそのまま詳細を開いて編集・メッセージ送信ができます
（`過去一覧` シートも `予約一覧` と同じ列構成のため）。

## 支店マスタの列構成

| 列 | 説明 |
|---|---|
| 支店コード | ログインID。JPロールの場合は `KANTO` / `KANSAI` のような任意のコードでも可 |
| 支店名 | 画面表示名（例: ウィーン支店、関東手配課） |
| 国 / 都市 | 検索・一覧表示に使用（支店ロールのみ設定） |
| ロール | `BRANCH` または `JP` |
| 手配チーム | JPロールのみ。`関東` または `関西`（"管轄"列の値と一致させる） |
| ログインパスコード | ログイン時の合言葉 |
| 通知先メール | メール通知の宛先（カンマ区切りで複数可） |
| 案件番号プレフィックス | BRANCHロールのみ。管理番号の先頭（支店ごとに一意、ローマ支店は`R`固定） |
| 有効 | falseにするとログイン不可 |

## 既存データ（旧ROW_fixed.gsの「予約一覧」）の移行について

旧シートの列名（`STS JPNROM`→`STS JP`、`STS ROMJPN`→`STS 支店`、`お名前01`→`新郎名（ローマ字）`など）
は本バージョンで整理しています。既存データを一括移行したい場合は別途対応しますので、必要であれば
お知らせください。
