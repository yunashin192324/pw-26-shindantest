# 動作テスト（開発者向け）

Google Apps Script の実行環境（SpreadsheetApp / MailApp / CacheService など）を
Node.js 上で模擬して、`Code.gs` のロジックを実際に動かして検証するテストです。
スプレッドシートやデプロイは不要で、手元ですぐ実行できます。

```bash
cd photowed-portal-gas/test
node gas_test.js
```

`結果: 190 件成功 / 0 件失敗` と表示されれば正常です。

## 何を検証しているか

| # | 項目 |
|---|---|
| 1 | 既存シートへの列追加（`setupPortal` 再実行で列が増え、既存データが壊れないこと） |
| 2 | やり取り履歴の書き込みが「列名基準」で正しい列に入ること |
| 3 | 納品期限アラート（過去一覧も走査／再通知／打ち切り／支店ごとの日数設定） |
| 4 | 過去一覧への移動で列がずれないこと |
| 5 | 統計ダッシュボードの内訳合計が件数と一致すること |
| 6 | 要対応（未読）判定と、既読にすると元の並び順に戻ること |
| 7 | ステータスの権限ゲート（日本側／支店側の書き分け、CR→CW/CF 制限など） |
| 8 | 支店のデータ分離（他支店の案件が見えない／統計はJP専用） |
| 9 | 新規案件の採番（アーカイブ済みと衝突しない）と通知先の向き |
| 10 | 現地記入欄・請求番号のカスタム名称 |
| 11 | 3択（保存のみ／メッセージのみ／変更＋メッセージ）の挙動 |
| 12 | 撮影45日前アラート |
| 13 | 支店マスタの表記ゆれ耐性（ロール・支店コードの大文字小文字／空白） |
| 14 | `apiSaveBranch` が他の列を消さないこと |
| 15 | 列が無い場合に分かりやすいエラーになること |
| 16 | 撮影日変更時に履歴・通知メールが正しい案件に紐づくこと |
| 17 | 既読チェックの認可（他支店の履歴を操作できない）と新規作成時の支店コード検証 |
| 18 | 未読フラグ方式（送信で立つ／既読で下りる／複数未読の扱い／履歴走査に依存しないこと） |
| 19 | 定期処理の例外処理（1件失敗しても継続）とシステム管理者への障害通知 |
| 20 | 未返信リマインド（既定3日／支店ごとの督促日数／既読で解除／複数案件を1通に集約） |
| 21 | 納品待ち一覧・当日スケジュール表・案件タイムライン（スコープと除外条件を含む） |
| 22 | ダブルブッキング検知（表記ゆれ吸収・支店をまたがない）・請求不備チェック・書き出し・定型文マスタ |
| 23 | 同意書（支店ごとの必須設定・通常フローでの手動更新・Googleフォーム連携での自動反映）・セール名（マスタ登録＋自由入力） |

## 注意

`gas_harness.js` はテスト用の簡易モックであり、Apps Script の完全な再現ではありません
（日付のタイムゾーン処理などは簡略化しています）。ロジックの回帰チェック用途に使ってください。
`Code.gs` を修正したら、このテストを実行してから反映することをおすすめします。
