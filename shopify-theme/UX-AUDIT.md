# UX検証レポート — 「これからプロポーズする男性」の目線で

対象: 世界のプロポーズプラン（TOP／旅行先ページ／予約リクエスト）。スマホ幅 390px と PC 幅 1280px で確認。

## 1. その人は誰で、何を考えているか

> 10月に彼女と旅行。出発は5日後。旅行中にプロポーズしたい。彼女にはバレたくない。スマホで検索して、5分で決めたい。

| 順番 | その人の頭の中 | 答えている場所（改善後） |
|---|---|---|
| 1 | 「そこで本当にできる？どんな場所がある？」 | TOP：場所タイル（ビーチ／チャペル／教会…）＋旅行先カード。旅行先ページ：**場所カード**（会場名つき） |
| 2 | 「間に合う？お金はいつ払う？」 | TOP：ヒーロー直下の安心4点。旅行先ページ：紹介文の直下 |
| 3 | 「当日はどう進む？」 | 当日の流れ（5ステップ） |
| 4 | 「結局いくら？写真は付く？」 | 3プランの**比較表**（花束／写真／動画／装飾）＋オプション |
| 5 | 「この日、空いてる？」 | 日程（今日から14日間）。雨の不安は日程のすぐ下に |
| 6 | 「バレない？失敗しない？」 | サプライズ配慮（安心4点）／FAQ の最初の質問 |
| 7 | 「早く申し込みたい」 | 場所と日時を選んで来ると、予約は残り3画面 |

## 2. 見つかった問題（改善前）

**重複**
- 旅行先ページで同じ写真が3回（冒頭・当日の流れ・締め）。TOP の当日の流れにも、上のカードと同じ他都市の写真。
- 「予約締切」「雨」「日本語サポート」「返信時間」が、概要表・日程の説明・FAQ・完了画面で3〜5回ずつ。
- 探す入口が2つ（場所の一覧と、景色タイル）で、役割が同じ。
- 3プランが縦に長いカード3枚で、「花束」「日本語サポート」が3回ずつ並ぶ（違いが見えにくい）。
- 予約画面の見出しにステップ名が2回（日本語と英語）。

**分かりにくい・見つけにくい**
- **場所の選択が奥にあった**：TOP では約4,600px 下、旅行先ページでは概要表のさらに下の小さなボタン。
- 「From ¥51,000」は花束だけの価格。写真も欲しい人が誤解する。
- 英語の見出し（Price／Book By／OPEN／Destination など）が先に来る。日本語の読者には遠回り。
- 旅行先ページの H1 に「プロポーズ」がなく、検索に弱い。
- 日付と時間が別の画面（1タップ余分）。
- 写真のない旅行先が、クリップアート風のイラストで「未完成」に見える。

**アクセシビリティ・文字**
- 文字色のコントラスト不足：TOP 37か所／旅行先ページ 36か所／予約 8か所（金色の英字ラベル、薄いグレー）。
- 9〜11.8px の小さな文字が全ページに。
- スキップリンクなし、ランドマーク（main など）の外にある内容。

**検索（SEO・AI検索）**
- H1 にキーワードなし。TOP に旅行先一覧の構造化データなし、旅行先ページに FAQ の構造化データなし、料金は1つだけ。
- フッターに旅行先ページへのリンクなし。タイトル・説明文の自動生成なし（空欄だと素っ気ない）。

## 3. 行った改善

| 課題 | 対応 |
|---|---|
| 場所が目立たない | TOP：カードの上に **6つのアイコンタイル**（押すと旅行先を絞り込み、会場名も表示）。旅行先ページ：紹介の直後に **大きな場所カード**。選んだ場所は予約まで引き継ぐ |
| 重複 | 事実は1か所だけに。3セクション（Last Minute／Place／Not Decided）を廃止・統合。写真の重複を解消（当日の流れは文章のみ、締めは別の切り出し） |
| プランの比較 | 1つの**比較表**に。行＝プラン、列＝花束／写真／動画／装飾／料金。スマホでも1画面で比べられる |
| 価格の誤解 | 「写真付き ¥128,000〜」と「花束のみ ¥51,000〜」の2本を併記 |
| 日本語ファースト | 見出し・ラベル・状態表示・予約のまとめをすべて日本語に（英語は小さな補助のみ） |
| 手数 | 日付と時間を1画面に。旅行先ページで場所と日時を選んで来れば、予約は残り3画面（プラン・情報・確認） |
| 安心 | ヒーロー直下に安心4点。予約画面の上部に常に「お支払いは確定後」 |
| 未完成に見える | 写真がない旅行先は、色のグラデーションと都市名の落ち着いたタイルに |
| 読みやすさ | 金色の文字を濃い金色に（コントラスト4.5:1以上）。最小文字サイズを12pxに |
| 検索 | H1 に「プロポーズ」。見出しに旅行先名。タイトル・説明文の自動生成。構造化データ（サイト／旅行先一覧／FAQ／3プランの価格／パンくず）。フッターに全旅行先リンク |

## 4. 検証結果

| 項目 | 改善前 | 改善後 |
|---|---|---|
| TOP の長さ（スマホ） | 12,370px | 9,071px |
| 文字色コントラスト不足（axe） | 37 / 36 / 8 か所 | **0**（3ページとも指摘なし） |
| 12px 未満の文字 | 全ページにあり（9〜11.8px） | **0** |
| その他 axe 指摘（ランドマーク・H1） | あり | **0** |
| Lighthouse（スマホ・公開ページ） | — | SEO **100**／アクセシビリティ **100** |
| 予約の画面数（旅行先が決まっていて、日時を選ぶところから） | 6画面（日付・時間・場所・プラン・情報・確認） | 5画面（日にち・時間を1画面に） |
| 自動ブラウザテスト（TOP→絞り込み→場所→日時→予約→送信、エラー時） | — | 28項目すべて合格 |
| スマホ幅 375/390/430、PC幅 1280/1440 | — | 横はみ出しなし |

※ Lighthouse の「予約ページ」のSEOが低いのは、検索に出さない設定（noindex）にしているためで意図どおりです。
※ 「console のエラー」は、検証環境が Google Fonts に接続できないことによるものです。

## 5. まだできていないこと・次の提案

1. **実ストアでの確認**（この検証は、Shopify のテーマを模擬データで描画して行いました）。公開前チェックリストで確認してください。
2. **TOP のヒーロー写真**：人物が写った「プロポーズの瞬間」の写真に差し替える（いまはカッパドキアの風景で、何のサービスか一目で伝わりにくい）。
3. **信頼の材料**：お客様の声、実績、フォトグラファーの紹介、実際の写真・動画のサンプル。**実在するものが揃ってから** 追加します（架空のものは載せません）。
4. **沖縄本島・グアムの写真**（いまは仮のタイル）と、会場ごとの写真。
5. **場所ごとの専用ページ**（例：ハワイ × ホテル）。会場の写真・流れ・注意点が揃ってから作ると、検索での効果が大きい。
6. **実際に使っての改善**：Shopify のアクセス解析で、場所タイル・場所カードのクリック率と、予約リクエストの完了率を見て調整する。
