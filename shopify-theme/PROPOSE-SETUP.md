# 世界のプロポーズプラン — Shopify 本番設定マニュアル

いまお使いの Shopify ストアに「世界のプロポーズプラン」のページを追加する手順です。
上から順に進めれば、次の 3 種類のページが公開されます。

| ページ | URL | 中身 |
|---|---|---|
| TOP | `/pages/propose` | 旅行先の一覧・当日の流れ・料金・FAQ |
| 旅行先ページ（12件） | `/pages/propose/hawaii` など | 写真・料金・当日の流れ・受付状況・FAQ |
| 予約リクエスト | `/pages/propose-booking` | 日時・プラン・オプション・お客様情報 → リクエスト送信 |

作業時間の目安は、ファイルの追加に 30 分、データの入力に 1〜2 時間です。

> 管理画面のメニュー名は Shopify の更新で少し変わることがあります。見つからない場合は、
> 管理画面上部の検索窓でメニュー名（例：「メタオブジェクト」）を検索してください。

## 0. 予約の仕組み（最初に確認してください）

**予約はリクエスト制です。サイト上ではお支払いは発生しません。**

```
お客様：旅行先ページで日時を選ぶ → プラン・オプション → お名前・メール → 「予約をリクエストする」
   ↓（Shopify のお問い合わせフォームとして、ストアのメールアドレスにリクエストが届く）
運営：フォトグラファーの手配を確認 → 24時間以内に返信
   ├ 手配できる → 下書き注文を作って「請求書を送信」 → お客様が支払う → 予約確定
   └ 手配できない → 近い日時を提案するメールを送る
```

- プランは 3 段階です。どのプランにも花束が入っています。

  | プラン | 内容 |
  |---|---|
  | ライトプラン（LIGHT PLAN） | 花束のみ |
  | スタンダードプラン（STANDARD PLAN） | 花束＋写真撮影 |
  | ラグジュアリープラン（LUXURY PLAN） | 花束＋写真撮影＋動画撮影＋デコレーション |

  オプションは「専用送迎・追加撮影30分・ベストタイム確保」の 3 つです。追加撮影は写真撮影付きのプランだけで選べます。
- **プロポーズの場所** は 6 種類から、旅行先ごとに選べるものを設定します（§4.2 の `place_types` と `〇〇_venues`）。
  お客様は旅行先ページの「どこで伝えますか？」と、予約フォームの「場所」のステップで選べます（おまかせ も可）。
  会場名を入れた種類では、会場まで指定できます。

  | 場所 | 旅行先（初期データ） | 会場名（初期データ） |
  |---|---|---|
  | ビーチ | ハワイ・宮古島・沖縄本島・グアム・バリ島 | — |
  | チャペル | ハワイ・宮古島・沖縄本島・グアム・バリ島・モルディブ | 沖縄本島：ラソール ガーデン・アリビラ／ラソール シーリゾート／ザ・サーフ ビーチサイドテラス／アートグレイス沖縄／サザンチャペル、モルディブ：フォーシーズンズ ランダーギラーヴァルのチャペル |
  | 教会 | ハワイ・イタリア | ハワイ：キャルバリー・バイ・ザ・シー教会 |
  | モニュメント | パリ・イタリア・サントリーニ島 | エッフェル塔／コロッセオ／サントリーニ島（イアの街並み） |
  | レストラン | ハワイ・モルディブ | — |
  | ホテル | すべての旅行先 | ハワイ：ハレクラニ／ザ・カハラ・ホテル＆リゾート、モルディブ：フォーシーズンズ ランダーギラーヴァル／ギリ ランカンフシ |

  **掲載する前に、各会場で実施できること・使用料・条件を会場と確認してください。** サイトには
  「会場の使用料や条件は会場ごとに異なるため、確定のご連絡でご案内します」と表示しています。
- 返信までの時間（初期値 24 時間）は §4.1 の「プロポーズ設定」で変えられ、サイト上のすべての表示に反映されます。
- 画面の「受付中／残りわずか／受付終了」は、運営が入力した受付終了枠をもとにした **目安** です。
  「受付中」でも確定ではないことを、サイト上でも明記しています。

## 2. テーマにファイルを追加する

### 2.1 まずテーマを複製する（安全のため）

1. 管理画面 **オンラインストア > テーマ**
2. 公開中のテーマの「…」 > **複製**
3. 以降の作業は複製したテーマで行い、§9 の確認が終わってから公開します。

### 2.2 ファイルを追加する

どちらか一方の方法で行います。

**方法 A：Shopify CLI（開発者の方向け・おすすめ）**

```bash
cd 世界のプロポーズプラン_Shopify一式/theme
shopify theme push --store あなたのストア.myshopify.com --theme <複製したテーマのID> --nodelete
```

`--nodelete` を付けるので、テーマにもともとあるファイルは消えません。

**方法 B：管理画面のコードエディタ**

1. 複製したテーマの「…」 > **コードを編集**
2. 下の表の順に、各フォルダで「新しいファイルを追加」してファイル名を入力し、zip 内の同名ファイルの中身を
   すべてコピーして貼り付け、保存します。
   - `assets` の 3 ファイルは「ファイルをアップロード」でもかまいません。
   - `templates/metaobject/propose.json` は、`templates` で「新しいテンプレートを追加」→ 種類「metaobject」を選べない場合、
     §4.2 でメタオブジェクト定義を作ってから追加してください（定義があると選べるようになります）。

| フォルダ | ファイル |
|---|---|
| layout | `propose.liquid` |
| snippets | `propose-header` `propose-footer` `propose-photo` `propose-plan-box` `propose-faq-list` `propose-place-type` （各 `.liquid`） |
| sections | `propose-hero` `propose-destinations` `propose-lastminute` `propose-steps` `propose-places` `propose-plan` `propose-faq` `propose-find` `propose-final` `propose-location` `propose-booking` （各 `.liquid`） |
| assets | `propose.css` `propose.js` `propose-booking.js` |
| templates | `page.propose.json` `page.propose-booking.json` `metaobject/propose.json` |

> スニペットより先にセクションを保存すると「スニペットがない」というエラーが出ることがあります。
> 表の順（layout → snippets → sections → assets → templates）で追加してください。

## 3. 写真をアップロードする

1. 管理画面 **コンテンツ > ファイル** > **ファイルをアップロード**
2. zip の `photos/` にある 10 枚（`propose-hawaii.jpg` など）をそのままアップロード
   - **沖縄本島とグアムの写真はまだありません。** 用意できたら `propose-okinawa.jpg` / `propose-guam.jpg` としてアップロードし、旅行先エントリーの写真に設定してください
     （未設定の間は「Photo coming soon」の仮表示になります）。

TOP ページの写真（ヒーロー・当日の流れ・景色から探す・締め）は、このファイル名を使って自動で表示されます。
同じ名前のファイルが既にあると Shopify が名前を変えるため、写真が出ない場合は §8 でテーマエディタから選び直してください。

- 各ファイルの「代替テキスト（alt）」に、`import/locations-data.csv` の「写真の代替テキスト」を入れてください（SEO とアクセシビリティのため）。
- 同梱の写真は Web 用に縮小した幅 1200px です。本番では **元の高解像度（幅 2000px 以上）** に差し替えることをおすすめします。
- **TOP のヒーロー写真は、プロポーズの瞬間（人物入り）の写真に差し替える前提です。** 現在はカッパドキアの風景を仮で使っています。

## 4. データの入れ物を作る（カスタムデータ）

### 4.1 メタオブジェクト「プロポーズ設定」（サイト全体の設定・1件だけ）

管理画面 **設定 > カスタムデータ > メタオブジェクト** > **定義を追加**

| 項目 | 値 |
|---|---|
| 名前 | プロポーズ設定 |
| タイプ（API ハンドル） | `propose_settings` |
| アクセス：ストアフロント | **オン** |

フィールド：

| 名前 | キー | タイプ |
|---|---|---|
| 返信までの時間 | `reply_hours` | 整数 |
| ライトプランに含まれるもの | `light_includes` | 単一行テキスト（**リスト**） |
| スタンダードプランに含まれるもの | `standard_includes` | 単一行テキスト（**リスト**） |
| ラグジュアリープランに含まれるもの | `luxury_includes` | 単一行テキスト（**リスト**） |

保存したら **コンテンツ > メタオブジェクト > プロポーズ設定** で **エントリーを 1 件だけ** 作ります。

- 返信までの時間：`24`（運営が実際に守れる時間を入れてください）
- ライト：`プロポーズ用の花束` / `日本語サポート`
- スタンダード：`プロポーズ用の花束` / `プロフォトグラファーによる写真撮影（30分）` / `写真データ30枚以上（オンライン納品）` / `日本語サポート`
- ラグジュアリー：スタンダードの内容 ＋ `動画撮影` / `プロポーズの場所のデコレーション`

（1 行ずつ入力。動画の長さやデコレーションの内容が決まったら、ここに書き足してください）

> このエントリーがない場合も、24 時間と上記の内容で表示されます。

### 4.2 メタオブジェクト「プロポーズ旅行先」（旅行先 1 件＝1 エントリー）

**設定 > カスタムデータ > メタオブジェクト** > **定義を追加**

| 項目 | 値 |

| 名前 | プロポーズ旅行先 |

| 機能：**Web ページ** | **オン**。URL ハンドル `propose`、テンプレート `propose`（§2 で追加したもの） |

| SEO：タイトル／説明に使うフィールド | `seo_title` ／ `seo_description`（選べる場合） |

フィールド（**キーは表の通りに**。名前は自由です）：

| 名前 | キー | タイプ | 必須 | 内容 |
|---|---|---|---|---|

| プラン商品 | `plan_product` | 商品 | ○ | §5 の「〇〇 プロポーズプラン」 |
| 所要時間 | `duration` | 単一行テキスト | ○ | 約2時間 |
| 集合場所 | `meeting_point` | 単一行テキスト | ○ | 当日の流れ・予約内容・リクエストメールに出ます |

### 4.3 商品メタフィールド（オプション商品用）

**設定 > カスタムデータ > 商品** > **定義を追加** を 4 回：

| 名前 | ネームスペースとキー | タイプ |
|---|---|---|
| 日本語名 | `propose.name_ja` | 単一行テキスト |
| 短い説明 | `propose.short_description` | 単一行テキスト |
| 送迎（ホテル入力が必要） | `propose.requires_hotel` | 真偽値（true / false） |
| 写真撮影付きプラン限定 | `propose.requires_photo` | 真偽値（true / false） |

- `requires_hotel` がオンのオプションを選ぶと、予約フォームに「ご滞在ホテル」の入力欄が出ます。
- `requires_photo` がオンのオプション（追加撮影）は、ライトプランでは選べません。

## 5. 商品を登録する

### 5.1 CSV でまとめて登録

1. **商品 > インポート** で `import/products.csv` を選ぶ（§4.3 を先に済ませておくと、メタフィールドも一緒に入ります）
2. 次の 15 商品ができます。

| 商品 | バリアント（上から順に） | 価格 |
|---|---|---|
| 〇〇 プロポーズプラン（12 件） | Light ／ Standard ／ Luxury | 例：ハワイ ¥51,000 ／ ¥128,000 ／ ¥228,000 |
| PRIVATE TRANSFER | — | ¥30,000 |
| EXTRA PHOTO | — | ¥20,000 |
| SUNSET TIME | — | ¥10,000 |

- **金額はすべて仮の値です。** 実際の料金に直してください。サイトの表示はすべて商品の価格から作られます
  （テーマ側に金額は書いていません）。
- バリアントは **1 番目がライト、2 番目がスタンダード、3 番目がラグジュアリー** として読み込みます。順番を入れ替えないでください（名前は変えてもかまいません）。
- 撮影サービスなので「配送が必要」はオフ、在庫は追跡しない設定で入ります。
- 税込表示にする場合は **設定 > 税金と関税** で「すべての価格に税金を含める」を確認してください。
- 各商品の販売チャネルに **オンラインストア** が入っていることを確認してください（入っていないとサイトに料金が出ません）。
- 商品ページ（`/products/propose-plan-hawaii` など）を検索に出したくない場合は、各商品の
  「検索エンジンのリスティング」で非表示にするか、ストアのナビゲーションに載せないでください。

### 5.2 オプション用のコレクション

**商品 > コレクション > コレクションを作成**

| 項目 | 値 |
|---|---|
| タイトル | プロポーズ オプション |
| ハンドル（URL） | `propose-options` （**必ずこの綴り**） |
| 種類 | 自動 ／ 条件：商品タグ が `propose-option` と等しい |
| 並べ替え | 価格の高い順（送迎 → 追加撮影 → ベストタイム の順になります） |

オプションを増やすときは、商品にタグ `propose-option` と §4.3 のメタフィールドを付けるだけで、
料金表と予約フォームに自動で加わります。

## 6. 旅行先を入力してページを作る

### 6.1 旅行先 12 件

**コンテンツ > メタオブジェクト > プロポーズ旅行先 > エントリーを追加**

- `import/locations-data.csv` を Excel で開き、1 行を 1 エントリーとして各欄を写します。
- エントリーの **ハンドル** は CSV の「ハンドル（URL）」（`hawaii` など）にしてください。URL になります。
- 「時間枠」「景色タグ」はリストなので、1 つずつ追加します。
- 保存時に **ステータスを「アクティブ」** にします（下書きのままだとサイトに出ません）。

### 6.2 TOP ページと予約ページ

**オンラインストア > ページ > ページを追加** を 2 回：

| タイトル | ハンドル | テーマテンプレート | SEO |
|---|---|---|---|
| 世界のプロポーズプラン | `propose` | `page.propose`（propose） | タイトル「世界のプロポーズプラン｜旅行先で、忘れられないプロポーズを。」／説明「旅行先はもう決まっている。あとは、その旅を一生忘れない一日に。ハワイ・パリ・宮古島など10の旅行先で、料金・当日の流れ・受付状況を確認して、そのまま予約をリクエストできます。」 |

## 7. 運用

### 7.1 リクエストが届いたら

リクエストは、ストアのお問い合わせフォームからのメールとして、**設定 > ストアの詳細** で設定している
ストアの連絡先メールアドレスに届きます（公開前に §9 のテスト送信で、どのアドレスに届くか確かめてください）。
本文には次の項目が並びます。

```
リクエスト番号 / 旅行先 / 希望日 / 時間 / 時間の調整 / プラン / 場所 / オプション / 合計 / 滞在ホテル / サプライズ配慮
（body に同じ内容のまとめ）
```

1. フォトグラファーの手配を確認（**返信までの時間以内に**）
2. **手配できる場合**：**注文管理 > 下書き > 下書き注文を作成**
   - 商品に「〇〇 プロポーズプラン」の該当バリアント（Light / Standard / Luxury）と、選ばれたオプション商品を追加
   - お客様：メールアドレスで検索、なければ新規作成
   - メモ：リクエスト番号・希望日・時間・会場・集合場所・ホテルを記載
   - チャペル・教会・レストラン・ホテルの使用料がかかる場合は、「カスタムアイテムを追加」で金額を入れてください
   - **請求書を送信**。送信画面で件名とメッセージを編集できます（下の文例）
   - お客様が支払うと注文になり、予約確定です。**その枠を `blocked_slots` に追加**（§7.3）
3. **手配できない場合**：近い日時を 2〜3 案添えて返信（下の文例）

### 7.2 メール文例

**サプライズ配慮「控えめな件名で連絡」の場合**、件名から「プロポーズ」を外してください
（相手と共有している端末で通知が見えることがあります）。

確定（請求書の送信画面で）

```
件名：ご旅行の撮影予約について（リクエスト番号 PRP-XXXXXX）
　※控えめ希望なし：【世界のプロポーズプラン】ご予約確定のご案内（PRP-XXXXXX）

〇〇様
ご希望の 10月3日（土）17:30 で、フォトグラファーの手配ができました。
下のボタンからお支払いいただくと、ご予約が確定します。
集合場所：〇〇
当日の2日前までに、担当から当日の詳細をお送りします。
```

代替のご提案

```
件名：ご旅行の撮影予約について（リクエスト番号 PRP-XXXXXX）

〇〇様
ご希望の 10月3日（土）17:30 は、あいにくフォトグラファーの手配ができませんでした。
次の日時でしたらご案内できます。
・10月3日（土）16:00
・10月4日（日）17:30
ご希望をこのメールへの返信でお知らせください。
```

### 7.3 受付状況（受付終了・残りわずか）の更新

旅行先エントリーの `blocked_slots`（受付終了）と `few_left_slots`（残りわずか）に 1 行ずつ入れます。

| 書き方 | 意味 |
|---|---|
| `2026-10-03 17:30` | その日のその時間だけ |
| `2026-10-03` | その日は終日 |

- `2026/10/3` のようにスラッシュでも読み取ります。
- プロポーズの日の `lead_time` 日前を過ぎた日は、自動で「締切」になります（入力不要）。
- 過ぎた日付は残っていても表示に影響しません。ときどき削除して整理してください。
- 受付状況は **サイトを見ている人の端末の日付** を基準に表示します。

### 7.4 料金・文章を変えるとき

| 変えたいもの | 場所 |
|---|---|
| 料金 | 商品のバリアント価格 |
| 返信までの時間・各プランに含まれるもの | コンテンツ > メタオブジェクト > プロポーズ設定 |
| 選べる場所・会場名 | 旅行先エントリーの `place_types` / `〇〇_venues` |
| 場所の説明文（「波の音が聞こえる砂浜で。」など） | `snippets/propose-place-type.liquid` |
| 旅行先の文章・写真・時間枠 | コンテンツ > メタオブジェクト > プロポーズ旅行先 |
| TOP の見出し・FAQ・当日の流れ・写真・旅行先の並び順 | オンラインストア > テーマ > カスタマイズ > ページ「世界のプロポーズプラン」 |
| 旅行先ページ共通の見出し・当日の流れ・FAQ | テーマ > カスタマイズ > メタオブジェクト「プロポーズ旅行先」 |
| 予約フォームの旅行先の並び順・規約リンク | テーマ > カスタマイズ > ページ「予約リクエスト」 |

FAQ などの文章では、次の記号が自動で置き換わります：
`{reply_hours}` 返信までの時間 ／ `{min_lead}` 最短の受付締切（TOP） ／
`{location}` 旅行先名 ／ `{meeting_point}` 集合場所 ／ `{lead_time}` 受付締切（旅行先ページ）

## 10. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 旅行先が 1 件も出ない | メタオブジェクトのタイプが `propose`、ストアフロントのアクセスがオン、エントリーがアクティブ |
| 旅行先ページが 404 | 定義の「Web ページ」がオン、テンプレートが `propose`、エントリーがアクティブ |
| 料金が出ない／予約フォームにその旅行先が出ない | `plan_product` が設定されている、商品が有効でオンラインストアに公開されている |
| オプションが出ない | コレクションのハンドルが `propose-options`、商品に `propose-option` タグ、オンラインストアに公開 |
| 写真が出ない | ファイル名が `propose-〇〇.jpg` か。違う場合はテーマエディタ／エントリーで選び直す |
| 送信後に画面が変わらない・エラー | スパム保護の確認画面が出ていないか。ストアのパスワード保護中はお問い合わせを送れない場合があります |
| リクエストのメールが届かない | 設定 > ストアの詳細 のメールアドレス、迷惑メールフォルダ |

## 11. ファイルと役割（開発者向け）

| ファイル | 役割 |
|---|---|
| `layout/propose.liquid` | 専用レイアウト。title／description／OGP／canonical、予約ページの noindex |
| `sections/propose-hero` 〜 `propose-final` | TOP の各セクション（テーマエディタで編集可） |
| `sections/propose-location.liquid` | 旅行先ページ本体。`metaobject` を読み、受付状況用の JSON を出力。Product／パンくずの構造化データ |
| `sections/propose-booking.liquid` | 予約リクエスト。旅行先・プラン・オプションを JSON で渡し、`{% form 'contact' %}` で送信 |
| `snippets/propose-plan-box.liquid` | 料金表（TOP・旅行先ページ共通） |
| `snippets/propose-photo.liquid` | 写真（srcset・遅延読み込み・トリミング位置） |
| `assets/propose.js` | ヘッダー・スクロール・FAQ・景色から探す・受付状況の判定（`window.ProposeAvail`） |
| `assets/propose-booking.js` | 予約ステップ、送信、完了画面（送信後はセッションストレージから復元） |
| `assets/propose.css` | デザイン（`propose-lp/src/styles.css` と同じ） |

- 画面の元は `propose-lp/`（モックアップ）です。見た目を変えるときはモックアップと両方に反映してください。
- 価格はすべて Liquid の商品価格（最小通貨単位）から計算し、JS では `shop.money_format` で整形します。
- テーマチェック（`@shopify/theme-check-node`）でエラーがないことを確認済みです（Google Fonts の外部読み込みの注意のみ）。
