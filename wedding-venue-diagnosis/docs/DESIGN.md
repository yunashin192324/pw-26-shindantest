# 結婚式場診断 設計・検証資料

## 1. 既存フォトウェディング診断（診断.txt）の解析

診断.txt に含まれているのは JavaScript のみで、HTML と CSS は含まれていません。画面の見た目は、同じ要素ID（`screen-start` `q-bar` `opts-single` など）を使っているこのリポジトリの `wedding-destination-quiz.html`（既存診断の改良版）を参照しました。

| 項目 | 既存診断の仕組み | 本診断での扱い |
|---|---|---|
| 開始画面 | 写真背景＋見出し＋「はじめる」の丸ボタン | 同じ構成（背景写真は設定で差し替え可能） |
| 質問画面 | 進捗バー、英字の区分名、質問文、補足文 | 同じ構成。「QUESTION 03」「3 / 7」の数字表示を追加 |
| 単一選択 | 下線区切りの行。押すと0.3秒後に自動で次へ | 同じ。戻ってきた場合は「次へ」ボタンも表示 |
| 複数選択 | 丸みのある枠のチェック項目＋「次へ」ボタン。未選択では次へ不可 | 同じ。「こだわらない」は他と同時に選べない。選択件数を表示 |
| 進行・戻る | `qFlow`（表示する質問の並び）を回答で変える。最初の質問で戻ると開始画面 | 同じ考え方。条件が2つ以上あるときだけ「最重視」質問を追加 |
| 回答の保持 | `answers` と `multiSel` の2か所に保持 | `answers` の1か所に統一（不整合を防ぐ） |
| 結果の算出 | 期間・予算で候補を絞り、各回答に固定の加点・減点 | Excel のカテゴリ一致数で並べる（後述） |
| 結果画面 | 1位の大見出し、一致率バー、一致／不一致の条件、カード、他の候補4件、相談ボタン、シェア | 同じ構成に「おすすめの理由」「条件ごとの一致表」を追加（全式場の一覧は表示しない） |

| スマホ表示 | 600px 以下で余白・文字・ボタンを縮小 | スマホ基準で作成し、文字を大きめ、ボタンは高さ44px以上 |
| 該当なし | 「条件に合うエリアが見つかりませんでした」と表示 | 「条件なし」「該当なし」を区別して案内し、回答の見直しへ誘導 |

### 既存コードの不具合（再現していないもの）
- 一致率の判定（`calcMatching`）が、点数計算とは別の対応表を使っており、点数と一致表示が食い違うことがある。→ 本診断は1つのデータ（Excel）だけを使う。
- 減点の結果、全候補が0点以下になると、候補があっても「見つかりませんでした」になる。→ 減点は使わない。
- 結果画面で予算の既定値が `1`、計算側では `5` と食い違っている。
- シェア文の改行が `\n` ではなく `n` になっている。
- 「こだわりなし」の解除を表示文字列の部分一致で行っている。
- コメントアウトされた `korea`・`studio` を参照する処理が残っている。
- 式場名などを、文字の無害化をせずに HTML として挿入している。→ すべて無害化して表示。
- 診断.txt 末尾の「これをみて、どのように答えたらどの都市になるかリスト化してほしい」は、コードとは別の依頼文と判断し、対象外としました。

## 4. 判定方法

数値の重みを決めて足し合わせる方式は、重みの根拠を示せないため採用せず、**比べる順番を決める方式**にしました。

1. 回答から希望条件（＝Excel カテゴリ）を集める。
2. 各式場について、Excel 上で該当する希望条件を数える。
3. 次の順に比べて並べる。
   1. 最も重視する条件に該当している式場が上（ユーザー自身が「いちばん」と選んだため）
   2. 該当した希望条件の数が多い式場が上（すべての条件は同じ1件として数えるため、1つの回答だけで結果が決まらない）
   3. 該当した条件が、より多くの質問にまたがっている式場が上（同じ数の一致なら、希望全体に広く合う方を上にする）
   4. ここまで同じなら**同順位**。表示は Excel の掲載順（行番号順）で、画面に「同率」と明記
4. 希望条件に1つも該当しない式場は「対象外」とし、おすすめしない。
5. 一致率 ＝ 該当した条件数 ÷ 選んだ条件数。

注意点（設計上の判断）：最重視の条件を選ぶと、その条件に該当する式場が、他の条件の一致数に関係なく上に来ます。質問文で「最優先でご提案します」と明示しています。この扱いを弱めたい場合は `js/logic.js` の `compareResults` を変更してください。

### 根拠の追跡
- 結果画面に「希望条件と、この式場の一致状況」（条件ごとに 該当／登録なし と、どの回答から来た条件か）を表示。
- 全式場の順位・一致数・該当条件は、画面には出さず `VENUE_DIAG.logic.diagnose()` の戻り値（`ranked`）で確認できます（テストで使用）。
- 「特徴の一覧を見る」で、その式場の全19カテゴリの登録状況を表示。

## 6. 未対応・残っている課題
- **写真がありません。** 背景写真・式場写真とも、実在の写真がないため設定していません（グラデーション背景で表示）。`js/config.js` の `sceneImages` と `js/data/venue-extras.js` の `image` に設定すると表示されます。
- 式場の地域・詳細ページURL・住所・料金は未設定です（Excel にないため）。
- 相談ボタンの URL は、既存診断で使われていた来店相談ページ（`https://www.his-wedding.com/special/shop_visit/`）を仮に設定しています。結婚式の相談先として適切かはご確認ください。オンライン相談のURLは、既存のものがフォトウェディング用の入力欄を含むため設定していません。
- データが粗い（カテゴリが19個で有無のみ）ため、同順位が多く出ます。同順位は画面で明示していますが、差をつけるには Excel 側のカテゴリを増やす必要があります。
- 文字の改行位置の調整（`word-break: auto-phrase`）は新しい Chrome 系のみ有効です。他のブラウザでは通常の改行になります（表示崩れはありません）。
- 実機（iPhone/Android 端末）での確認はしていません。Chromium の画面サイズを変えての確認のみです。
