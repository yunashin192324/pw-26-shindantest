# 結婚式場診断 設計・検証資料

## 1. 既存フォトウェディング診断（診断.txt）の解析

診断.txt に含まれているのは JavaScript のみで、HTML と CSS は含まれていません。画面の見た目は、同じ要素ID（`screen-start` `q-bar` `opts-single` など）を使っているこのリポジトリの `wedding-destination-quiz.html`（既存診断の改良版）を参照しました。

| 項目 | 既存診断の仕組み | 本診断での扱い |
|---|---|---|
| 開始画面 | 写真背景＋見出し＋「はじめる」の丸ボタン | 同じ構成（背景写真は設定で差し替え可能） |
| 質問画面 | 進捗バー、英字の区分名、質問文、補足文 | 同じ構成。「QUESTION 03」「3 / 7」の数字表示を追加 |
| 単一選択 | 下線区切りの行。押すと0.3秒後に自動で次へ | 同じ。戻ってきた場合は「次へ」ボタンも表示 |
| 複数選択 | 丸みのある枠のチェック項目＋「次へ」ボタン。未選択では次へ不可 | 同じ。「こだわらない」は他と同時に選べない。選択件数を表示 |
| 進行・戻る | `qFlow`（表示する質問の並び）を回答で変える。最初の質問で戻ると開始画面 | 同じ考え方。条件が2つ以上あるときだけ「最重視」質問を追加 |
| 回答の保持 | `answers` と `multiSel` の2か所に保持 | `answers` の1か所に統一（不整合を防ぐ） |
| 結果の算出 | 期間・予算で候補を絞り、各回答に固定の加点・減点 | Excel のカテゴリ一致数で並べる（後述） |
| 結果画面 | 1位の大見出し、一致率バー、一致／不一致の条件、カード、他の候補4件、相談ボタン、シェア | 同じ構成に「おすすめの理由」「条件ごとの一致表」を追加（全式場の一覧は表示しない） |
| 画像・リンク | 外部の画像URL・ページURLを各エリアに設定 | Excel に無いため設定しない（追加情報ファイルで後から設定可能） |
| 演出 | 画面のぼかしフェード、文字のせり上がり、読込中の名前スロット | 同じ演出。動きを減らす設定の端末では短縮 |
| スマホ表示 | 600px 以下で余白・文字・ボタンを縮小 | スマホ基準で作成し、文字を大きめ、ボタンは高さ44px以上 |
| 該当なし | 「条件に合うエリアが見つかりませんでした」と表示 | 「条件なし」「該当なし」を区別して案内し、回答の見直しへ誘導 |

### 既存コードの不具合（再現していないもの）
- 一致率の判定（`calcMatching`）が、点数計算とは別の対応表を使っており、点数と一致表示が食い違うことがある。→ 本診断は1つのデータ（Excel）だけを使う。
- 減点の結果、全候補が0点以下になると、候補があっても「見つかりませんでした」になる。→ 減点は使わない。
- 結果画面で予算の既定値が `1`、計算側では `5` と食い違っている。
- シェア文の改行が `\n` ではなく `n` になっている。
- 「こだわりなし」の解除を表示文字列の部分一致で行っている。
- コメントアウトされた `korea`・`studio` を参照する処理が残っている。
- 式場名などを、文字の無害化をせずに HTML として挿入している。→ すべて無害化して表示。
- 診断.txt 末尾の「これをみて、どのように答えたらどの都市になるかリスト化してほしい」は、コードとは別の依頼文と判断し、対象外としました。

## 2. Excel（診断.xlsx）の確認結果

- シート1「式場リスト」：A列が式場名、B〜T列（19列）がカテゴリ。セルに文字が入っていれば該当、という想定は正しいことを確認しました。入っている文字はすべて列見出しと同じ文字でした（不一致0件）。
- シート2「カテゴリ」：19件。シート1の列見出しと、順番・表記とも完全に一致。
- 式場数 51件（2〜52行目）、重複なし、カテゴリ未設定の式場なし、非表示の行・列なし、結合セルなし。付与されたカテゴリは合計327個。
- カテゴリごとの該当式場は [DATA_REPORT.md](DATA_REPORT.md) を参照（自動生成）。

### 気になった点（修正はしていません）
1. **式場の地域・画像・URL・住所・料金が Excel にありません。** そのため画面には表示していません。入力用の `source/式場追加情報.xlsx` を用意し、`tools/build_extras.py` で取り込めるようにしました。
2. **8行目「ザ・プライベート・ガーデン・アロハ・ケ･アクア」の「ケ･アクア」の中点だけが半角（･）**で、他の式場名は全角（・）です。ご指示により、全角（・）に統一しました（`source/診断.xlsx` を修正）。お手元の元ファイルは半角のままです。
3. **カテゴリが付いていないことが「対応していない」ことを意味するのかは、Excel からは判断できません。** 例：「子供と一緒」は22式場のみ。そのため画面では「× 対応不可」ではなく「－ 登録なし」と表示し、詳細画面にも注記しています。
4. 「フライト時間が短い」20式場のうち5式場（30〜34行目）は「時差がない」が付いていません。矛盾ではありませんが、事実関係は Excel からは確認できません。
5. 「時差がない」の15式場はすべて「フライト時間が短い」にも該当し、「ビーチが目の前」の19式場はすべて「海が見える」にも該当します（矛盾なし）。
6. 「コスパ重視」「衣裳重視」「写真にこだわる」は、式場の設備ではなく評価に近いカテゴリです。付与の基準は Excel に書かれていないため、わかりません。そのまま使っています。
7. リポジトリ内の `hawaii-chapel-diagnosis.html` とは、同じ式場と思われる名前の表記が異なります（例：Excel「ディズニー・フェアリーテール・ウエディング・アウラニ」／既存「〜ウェディング〜」、「ハレクラニウェディング」／「ハレクラニウエディング」）。今回は Excel を正としました。将来データを統合する場合は名寄せが必要です。

## 3. 診断の流れ（販売店スタッフの接客手順に合わせた版）
1. **国・地域**：ハワイ（オアフ島）／沖縄／グアム／バリ島／オーストラリア（ケアンズ）／ヨーロッパ／モルディブ／ニュージーランド／北海道／まだ決めていない
2. **お子さまの参列**（はい → 子供と一緒）
3. 地域が未定のとき：**日数**（3〜5日／6〜7日／8日以上／まだ分からない）→ **おすすめの地域から選ぶ**
   - 3〜5日：グアム・沖縄・北海道、6〜7日：＋ハワイ・バリ島・ケアンズ、8日以上：＋ヨーロッパ・モルディブ・ニュージーランド
   - お子さま連れ：グアム → 沖縄 → バリ島 → ハワイ → ケアンズ の順（js/config.js の kidsRegionOrder）
4. 地域ごとの質問
   - **ハワイ**：挙式スタイル（白系の海の見えるチャペル／茶系の海の見えるチャペル／本格的な教会／オープンエアのガーデン）→ チャペルなら海の見え方（ビーチが目の前／高台でもよい）、教会なら雰囲気（アットホーム／ステンドグラス／海が見える）→ 移動（ホテル内／30分圏内／60分程度でもよい）
   - **沖縄**：島選び（本島／宮古島／石垣島）→ 本島なら立地（南部／恩納村・読谷／宜野座・名護・北部）→ 挙式スタイル → 式場の場所（ビーチが目の前／ホテル内／独立型）
   - **グアム**：挙式スタイル → 式場の場所
   - **バリ島**：挙式スタイル → 式場の場所 → 滞在の過ごし方（マリンアクティビティ＝ベノア／のんびり＝ヌサドゥア）
   - **ヨーロッパ**：ステンドグラスにこだわるか（こだわる場合はフィレンツェ → パリ の順）→ 撮影スポット（エッフェル塔／コロッセオなど世界遺産／フィレンツェの街並み）
   - **ケアンズ**：式場の場所。**モルディブ・ニュージーランド・北海道**：式場1件のため質問なし
5. **そのほかのこだわり**（同じ敷地でパーティ／ガーデンでパーティ／料理／写真／衣裳／費用／ヴィラ／キャラクター）
6. **いちばん重視する条件**（絞り込みに使っていない条件が2つ以上のとき）

自動で省略・非表示にするもの：
- 選んだ地域の候補に当てはまる式場が無い選択肢、全候補に当てはまり違いが出ない選択肢は表示しない（例：沖縄は全式場が「子供と一緒」のため、お子さまの質問を出さない）
- 違いの出る選択肢が無い質問、候補が1件以下になった後の質問は出さない

## 4. 判定方法
- 候補：選んだ地域の式場。沖縄の島選びはエリアで、挙式スタイルは該当する式場だけに絞る。
- 並び順：①最重視の条件に該当 → ②該当した希望条件の数 → ③回答で決まる順（ステンドグラス重視のフィレンツェ→パリ）→ ④人気順（式場追加情報.xlsx）→ ⑤診断.xlsx の掲載順。①②が同じなら「同率」と表示。
- 希望条件に1つも該当しない式場はおすすめしない。条件が無い（例：モルディブ）または誰も該当しない場合は、選んだ地域の式場を人気順に案内し、その旨を表示する。
- 以前の「該当した条件がいくつの質問にまたがるか」の比較は、質問の作りが変わり意味がなくなったため廃止。

### 判定に使う情報（すべて Excel に記録）
- 診断.xlsx：19カテゴリ。うち「ガーデンがある」「教会・大聖堂」以外の挙式スタイル判定、「フライト時間が短い」「時差がない」「自然豊か」「世界遺産」は、地域・日数の質問に置き換えたため現在は使っていない（「教会・大聖堂」は教会の選択肢で使用）。
- 式場追加情報.xlsx：エリア、人気順、挙式スタイル、内観の色、立地・地区、ワイキキからの移動、ガーデンでパーティ、撮影スポット。ここから「挙式：チャペル」「内観：白系」「立地：南部」「ワイキキから30分圏内」「独立型」（ホテル内でない式場）などの特徴を作る。
- js/config.js：地域と日数の対応、お子さま連れのおすすめ順。

### 根拠の追跡
- 結果画面に、希望条件ごとの 該当／登録なし と、どの回答から来た条件かを表示。
- 「特徴の一覧を見る」で、診断.xlsx の19カテゴリと、追加情報の特徴を表示。

## 6. 未対応・残っている課題
- **写真がありません。** 背景写真・式場写真とも未設定です（グラデーション背景で表示）。`source/式場追加情報.xlsx` に入力して `tools/build_extras.py` を実行すると表示されます。
- 式場の地域・詳細ページURL・住所・料金は未設定です。`source/式場追加情報.xlsx` に入力欄があります。
- 相談ボタンの URL は、既存診断で使われていた来店相談ページ（`https://www.his-wedding.com/special/shop_visit/`）を仮に設定しています。結婚式の相談先として適切かはご確認ください。オンライン相談のURLは、既存のものがフォトウェディング用の入力欄を含むため設定していません。
- データが粗い（カテゴリが19個で有無のみ）ため、同順位が多く出ます。同順位は画面で明示していますが、「同点時の表示順」（式場追加情報.xlsx）で並び順を決められます。
- 文字の改行位置の調整（`word-break: auto-phrase`）は新しい Chrome 系のみ有効です。他のブラウザでは通常の改行になります（表示崩れはありません）。
- 実機（iPhone/Android 端末）での確認はしていません。Chromium の画面サイズを変えての確認のみです。
