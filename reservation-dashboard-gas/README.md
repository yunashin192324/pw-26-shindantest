# 営業セールスダッシュボード（Googleスプレッドシート + GAS）

営業日報CSVのうち、以下19項目だけを抽出して蓄積し、分析するダッシュボードです。
Googleスプレッドシートと Google Apps Script（GAS）のみで構築しており、Webアプリとして利用します。
UI/UX は添付いただいた「46期リセール管理システム」の配色・レイアウト（ヘッダーのKPIカード、タブ切り替え、
固定見出しの一覧表、モーダル、トースト通知など）を踏襲しています。

## 抽出対象の19項目

| CSV列番号 | 項目名 |
|---|---|
| 006 | エリア |
| 007 | 営業所 |
| 013 | 最終目的地 |
| 014 | 予約日 |
| 016 | 出発予定日 |
| 019 | 顧客ID |
| 020 | 予約番号 |
| 023 | 性別 |
| 024 | 国籍 |
| 029 | 商品分類 |
| 031 | キャリア |
| 037 | ツアーブランド区分 |
| 038 | ツアーコード |
| 046 | 売上(商品請求金額) |
| 047 | 入金額 |
| 051 | STS |
| 058 | 担当者 |
| 070 | 商品タイトル |
| 076 | 旅行日数 |

CSVの見出しが `006:エリア` のように「列番号：項目名」の形式であれば、列の並び順が変わっても
項目名だけで自動的に列を判定して取り込みます。上記以外の列（69項目分）は取り込み時に読み捨てます。

## 現場で入力する項目（CSVには無く、画面から直接入力する）

CSV由来19項目に加えて、「予約データ」シートの20〜33列目に以下14項目を追加しています。
これらはCSVインポート時は空欄のまま追加され、Webアプリの「予約データ一覧」タブから直接入力・編集します。

| 項目 | 内容 |
|---|---|
| CHK日 | 日付を直接入力 |
| 保険 / 保険数量 / 保険理由 | ステータス（下記5段階）と数量（加入PAX数）、失注時の理由 |
| Wifi / Wifi数量 / Wifi理由 | 同上（数量＝販売台数） |
| TAViCA / TAViCA数量 / TAViCA理由 | 同上（数量＝加入数） |
| キャンサポ / キャンサポ数量 / キャンサポ理由 | 同上（数量＝加入PAX数） |
| メモ | 自由記述（一覧では10文字まで表示し、超える場合はカーソルを合わせると全文をポップアップ表示） |

### 保険・Wifi・TAViCA・キャンサポのステータス（5段階）

| 表示 | 意味 |
|---|---|
| － | NO ACT（既定値） |
| 〇 | NB付帯 |
| × | 失注 |
| △ | セールス中 |
| ☆ | PUSH成約 |

- **「×（失注）」を選択すると**、数量は自動的に0に固定され、失注理由の入力を求めるダイアログが表示されます。
  入力した理由は画面上に反映され、一覧表でステータス・数量にカーソルを合わせる（スマホ版はカードに直接理由を表示）と確認できます。
  ダイアログをキャンセルした場合はステータスの変更自体が取り消されます（この時点ではまだサーバーには保存されません。後述）。
- **「〇（NB付帯）」または「☆（PUSH成約）」を選択したのに数量が未入力の場合**、警告のトースト通知が表示されます
  （画面上の注意喚起であり、入力自体をブロックするものではありません）。
- 上記以外のステータス（－・△）に変更すると、数量・理由は自動的に空欄に戻ります。

## 編集の保存方法（まとめて保存する）

予約データ一覧のCHK日・保険/Wifi/TAViCA/キャンサポ・メモは、1項目編集するたびに即座にサーバーへ保存するのではなく、
他のリセール管理システムと同様に**画面上でいったん保留し、「まとめて保存する」を押した時点でまとめてサーバーへ反映**します。

- 編集すると、画面上部（予約データ一覧タブ）に「✏️ 未保存の変更：N件」というオレンジ色のバーが表示され、
  編集したセルにもオレンジの枠が付きます。
- **「まとめて保存する」**を押すと、保留中の変更を1回のサーバー呼び出しでまとめて保存します。閲覧範囲外に
  なった行など、一部の変更が反映できなかった場合はその件数を知らせます。
- **「取り消す」**を押すと、保留中の変更をすべて編集前の状態に戻します（確認ダイアログが出ます）。サーバーには
  何も送信されません。
- ページを再読み込みしたり別のタブに移動しても保留中の変更は消えないよう画面上は保持されますが、
  実際にはブラウザのメモリ上にあるだけなので、ページを閉じたり再読み込みしたりすると保存前の変更は失われます。
  未保存の変更がある間は保存を忘れずに行ってください。
- 「一括登録」（複数行を選択して同じ値をまとめて登録する機能）は、この保留の仕組みとは別に、
  「適用」を押した時点で即座にサーバーへ保存されます。

## 権限（スタッフ権限シート）

初期セットアップを実行すると、データ用の「予約データ」シートに加えて「スタッフ権限」シートも作成されます。
列は `Googleアカウント・氏名・所属店舗・所属エリア・権限` の5列で、権限は次の3段階です。

| 権限 | 閲覧範囲 | CSVインポート |
|---|---|---|
| 社員 | 自分の「所属店舗」と一致する営業所の行のみ | 不可 |
| 所長・チーフ | 自分の「所属エリア」と一致するエリアの行のみ | 不可 |
| マスタ権限 | 全エリア | 可能（重複削除・全削除・権限管理も可能） |

**「スタッフ権限」シートに1件も登録が無い間は、誰でもマスタ権限として扱われます**（最初のセットアップができるようにするための仕様です）。
運用を始める前に、必ず自分自身のGoogleアカウントを「マスタ権限」で1行登録してください。
登録が無いままの状態で他のメンバーに共有すると、全員がマスタ権限として全データを閲覧・操作できてしまいます。

スタッフ権限シートに登録済みでもいずれの権限にも一致しないアカウント（メールアドレスが1件も無い等）でアクセスすると、
「アクセス権がありません」という案内が表示され、データは一切表示されません。

Webアプリからも、「データ管理」タブの「権限管理（スタッフ権限）」からアカウントの追加・編集・削除ができます
（マスタ権限のユーザーのみ操作できます）。

## 予約データ一覧の列の並び順

「予約データ一覧」タブの列は、初期状態では以下の順です（ご指定いただいた並び順をもとにしています）。

```
予約番号 → 担当者 → 出発予定日 → CHK日 → メモ → 保険 → Wifi → キャンサポ → TAViCA(TVC) →
予約日 → 最終目的地 → 旅行日数 → 商品分類 → ツアーブランド区分 → ツアーコード → キャリア →
売上(商品請求金額) → 入金額 → STS → 商品タイトル → 営業所
```

「データ管理」タブの「予約データ一覧の列の並び順」から、▲▼ボタンで並び替えて保存できます
（どの権限のユーザーでも並び替えできます）。保存するとスプレッドシート単位で記録され、
他のメンバーがWebアプリを開いたときにも同じ並び順で表示されます。
「エリア」「顧客ID」「国籍」「性別」の4項目は、ご指定に従って一覧表からは削除しています
（絞り込み検索や個人別サマリーでは引き続き使用します）。

## 予約データ一覧の一括登録

各行のチェックボックスで複数行を選択すると、「一括登録」欄からCHK日・メモ・保険/Wifi/キャンサポ/TAViCAの
ステータス（数量）を選択した行すべてに同じ値でまとめて登録できます（1件ずつ手入力する手間を省けます）。

- CHK日・メモ：入力欄に値を入れて「適用」を押すと、選択した行すべてに同じ値が設定されます。
- 保険/Wifi/キャンサポ/TAViCA：プルダウンでステータスを選び（〇・☆の場合は数量も入力し）「適用」を押します。
  「×（失注）」を選んだ場合は、通常の1行編集と同様に失注理由の入力を求められ、選択した行すべてに
  同じ理由が登録されます。
- 自分の閲覧範囲外の行が選択に含まれていた場合、その行だけは反映されず、結果に反映件数が表示されます。

## ヘッダーのKPIカード

ヘッダーには「予約件数・保険契約数・Wifi販売台数・キャンサポ契約数・TAViCA契約件数」の5枚のカードを表示します
（キャンサポをTAViCAより先に表示する順に統一しています）。
値は分析ダッシュボードタブの現在の絞り込み結果に連動します。

## ダッシュボードのフィルタ（タブごとに別々です）

- **分析ダッシュボードタブ**：エリア・営業所・商品分類・ツアーブランド区分・方面別（最終目的地）・
  基準日（予約日／出発予定日／CHK日）・期間（From〜To）
- **予約データ一覧タブ**：エリア・店舗（営業所）・担当者・出発予定日（From〜To）・保険/Wifi/TAViCA/キャンサポそれぞれのSTS（－〇×△☆）

キーワード検索は廃止し、各付帯商品のSTSによる絞り込みに置き換えています。
ヘッダーのKPIカードと分析ダッシュボードのグラフ・ランキングは、分析ダッシュボードタブのフィルタに連動します。

予約データ一覧タブの「エリア」「店舗」「担当者」は連動します。エリアを選ぶと店舗の選択肢が同じエリアの
店舗だけに絞り込まれ、店舗を選ぶと担当者の選択肢が同じ店舗の担当者だけに絞り込まれます。担当者の選択肢は
担当者マスタに登録があれば氏名で表示します（コードのままでは表示しません）。

## 分析ダッシュボードのグラフ

保険・Wifi・キャンサポ・TAViCAの4種の付帯商品について、以下のグラフ・実績データを表示します。
最も確認頻度の高い指標のため、付帯商品ごとのグラフをダッシュボードの一番上に配置しています。

- **付帯商品ごとのグラフ**（保険／Wifi／キャンサポ／TAViCA、2列×2行で表示）：棒＝リスト数（予約件数）、
  折れ線＝加入・販売数（数量合計）を月別に表示します。
- **NB付帯・PUSH成約の実績**：各グラフの見出し下に、現在の絞り込み結果における「NB付帯（〇）」「PUSH成約（☆）」それぞれの実績件数を表示します。
- **付帯商品 総合（月別販売数）**：4種すべての月別数量（加入・販売数）を1つの折れ線グラフに重ねて表示し、
  商品間の比較ができます。
- **商品分類別／方面別（最終目的地）／キャリア別**（2列で表示）：方面別グラフは、棒＝方面ごとの予約件数（上位10）、
  折れ線＝同じ方面の保険・Wifi・キャンサポ・TAViCA各付帯の販売数量を重ねて表示します。
- **営業所別ランキング**：個人別サマリーと同じ形式（エリア・営業所名・担当者・記録件数・付帯商品ごとの
  合計／NB付帯／PUSH成約）で表示します。

## 個人別サマリータブ

エリア・営業所・担当者ごとに、記録件数と保険・Wifi・キャンサポ・TAViCAの実績を集計して一覧表示します
（列の並び順：エリア → 営業所名 → 担当者 → 記録件数 → 保険 → Wifi → キャンサポ → TAViCA）。
あなたが閲覧できる範囲（権限による絞り込み後）のデータが対象です。エリア・営業所名・担当者名で検索できます。
担当者マスタに氏名が登録されている場合は、担当者コードの代わりに氏名を表示します。

各付帯商品の数値は「合計（数量の合計）／NB付帯（〇のステータスの件数）／PUSH成約（☆のステータスの件数）」の
3つを1つのセルにまとめて表示します。

## 担当者マスタ（担当者コード→氏名の変換）

初期セットアップを実行すると、「担当者マスタ」シートも作成されます。列は `担当者コード・氏名` の2列です。

CSVの「担当者」列にはコード（例：`BGK078`）がそのまま入りますが、「データ管理」タブの「担当者マスタ」から
コードと氏名を対応付けて登録すると、「予約データ一覧」「個人別サマリー」の担当者列がコードの代わりに
氏名で表示されます（マスタ権限のユーザーのみ登録・編集・削除できます）。未登録のコードはそのままコード表示されます。

この変換は表示上のみの処理で、シート上の「担当者」列の値（コード）自体は変更されません。
そのため、CSV再取込時の重複判定やCSV由来項目には一切影響しません。

### 人事データCSVインポート（担当者マスタへの一括反映）

「担当者マスタ」カードの「人事データCSVインポート」から、人事システムなどから出力したCSVを取り込むと、
担当者コードと氏名の対応をまとめて登録・更新できます。

- CSVの見出し行にある「■担当者NO」列と「社員名称」列だけを使います（先頭の「■」の有無は問いません）。
  それ以外の人事項目の列（部署・入社日など）は読み捨てます。
- 「■担当者NO」の値が担当者マスタに既に登録されていれば氏名を上書き更新し、未登録であれば新規追加します。
- CSV内に同じ担当者NOが複数行ある場合は、CSV内の最後の行を採用します。
- 見出し行から「■担当者NO」「社員名称」の両方が検出できない場合はエラーになり、取り込みは行われません。

### 人事データCSVからのGoogleアカウント（スタッフ権限）一括登録

同じ人事データCSVに、Googleアカウント（メールアドレス）の列も含まれている場合は、「権限管理（スタッフ権限）」への
一括登録もあわせて行います。所属店舗・所属エリア・権限の列があれば、それも読み取って設定します。

- Googleアカウント列は「Googleアカウント」「メールアドレス」「メール」「Email」「Gmailアドレス」などの表記を自動検出します。
  所属店舗は「所属店舗」「店舗」「駐在所属名称」、所属エリアは「所属エリア」「エリア」「エリア名」、
  権限は「権限」「役職」「役割等級」などの表記を自動検出します
  （列名が一致しない場合、該当する項目は空欄のまま登録されます）。
- 権限の判定は、該当列の値に「所長」または「チーフ」という文言が含まれていれば「所長・チーフ」、
  それ以外（「エリアリーダー」「スタッフ」など）は「社員」とします。
- メールアドレスの形式が正しくない行はスキップします。
- 既にスタッフ権限に登録済みのGoogleアカウントは、氏名・所属店舗・所属エリアのみ更新します。
  **権限（社員／所長・チーフ／マスタ権限）は、既存ユーザーについては一切変更しません**
  （システムへのアクセス権限は、人事データの更新では変えないという方針です）。
- 新規のGoogleアカウントは、CSVの「権限」欄の文言から社員・所長・チーフを判定して登録します
  （「所長」「チーフ」「店長」を含む場合は所長・チーフ、それ以外は社員）。
  CSVの権限欄が「マスタ権限」「管理者」等であっても、**安全のため自動ではマスタ権限を付与せず、社員として登録します**。
  マスタ権限が必要な場合は、取り込み後に「権限管理（スタッフ権限）」画面から手動で変更してください。
- CSVにGoogleアカウントの列が無い場合は、これまで通り担当者マスタ（氏名表示）のみを更新し、
  スタッフ権限には一切手を加えません。

## 予約番号（記録番号／チャレンジ番号）→「チャレンジ記録」へのリンク

「予約データ一覧」の予約番号は、値が**半角英数字ちょうど11文字**のときだけ自動的にリンクになり、
クリックすると新しいタブで「チャレンジ記録」（外部システム）の該当ページが開きます。
11文字でない場合や、全角文字・空白が混ざっている場合はリンク化されず、通常のテキストとして表示されます。

リンクは、あらかじめ決まっているベースURLの末尾に予約番号（11文字）をそのまま連結して作られます。

```
ベースURL：http://applweb.center.his/cgi-bin/b/btcq1_0_3ui?scid=_new&rsv=01102
例）予約番号が「12345678901」の場合
→ http://applweb.center.his/cgi-bin/b/btcq1_0_3ui?scid=_new&rsv=0110212345678901
```

ベースURLは `Javascript.html` の `CHALLENGE_RECORD_BASE_URL`（オフラインモックアップでは各HTMLファイル内の
同名の変数）1箇所にまとめているため、URLが変更になった場合はそこだけ書き換えれば反映されます。

※ 「記録番号」はCSV上に独立した列としては存在せず、「予約番号（CSV列番号020）」が
　11桁のチャレンジ番号と同じ形式であるという整理のもと、予約番号列にこの機能を実装しています。
　対象項目の認識が違う場合はお知らせください。

## ファイル構成

```
reservation-dashboard-gas/
├─ appsscript.json   … GASプロジェクトのマニフェスト（タイムゾーン・Webアプリ設定）
├─ Code.gs           … バックエンドAPI（doGet、CSVインポート、データ管理）
├─ InitSheet.gs       … シート初期化（メニュー実行）
├─ Index.html         … 画面のHTML構造
├─ Javascript.html    … 画面のロジック（フィルタ・集計・グラフ描画）
└─ mockup/index.html … オフラインPCでも開けるUI/UXモックアップ（後述）
```

## 導入手順

1. **新しいGoogleスプレッドシートを作成する**
   （このスプレッドシートがそのままデータベースになります。実データを入れるので、
   共有設定は業務で扱う顧客データに準じた権限にしてください。）

2. **拡張機能 → Apps Script** を開く。

3. デフォルトで作られている `コード.gs`（または `Code.gs`）の中身を全て削除し、
   このフォルダの `Code.gs` の内容を貼り付けて保存する。

4. 左側の「＋」から **スクリプト** を追加し、ファイル名を `InitSheet` にして
   `InitSheet.gs` の内容を貼り付ける（拡張子 `.gs` は自動で付きます）。

5. 同様に **HTML** ファイルを2つ追加する。
   - ファイル名 `Index` → `Index.html` の内容を貼り付け
   - ファイル名 `Javascript` → `Javascript.html` の内容を貼り付け

6. プロジェクトの設定（歯車アイコン）で「`appsscript.json` マニフェスト ファイルをエディタで表示する」
   にチェックを入れ、`appsscript.json` の中身をこのフォルダの `appsscript.json` の内容に置き換える
   （Webアプリのアクセス範囲 `access` は組織の運用に合わせて `DOMAIN` / `ANYONE` などに調整してください）。

7. 保存したら、一度スプレッドシートのタブを開き直す（またはApps Scriptエディタで `onOpen` を
   一度実行して権限を承認する）。スプレッドシートのメニューに **「営業セールスダッシュボード」** が追加されます。

8. メニュー **「営業セールスダッシュボード」→「① 初期セットアップ（シート作成）」** を実行する。
   `予約データ` シート（33列・見出し付き）、`スタッフ権限` シート、`担当者マスタ` シートが作成されます。
   ※ Webアプリ側の「初期セットアップを実行する」ボタンからも同じ処理を実行できます。

9. **「スタッフ権限」シートに、自分自身のGoogleアカウントを「マスタ権限」で1行登録する。**
   （これを忘れると、他のメンバーに共有した際に全員がマスタ権限として扱われてしまいます。）

10. Apps Scriptエディタの **デプロイ → 新しいデプロイ** を実行する。
    - 種類：**ウェブアプリ**
    - 実行ユーザー：**自分**
    - アクセスできるユーザー：組織の運用に合わせて選択
    - デプロイ後に表示される **ウェブアプリのURL** を利用者に共有する。

11. Webアプリを開き、「データ管理」タブの **CSVインポート**（マスタ権限のみ表示）から営業日報CSVを取り込む。

12. 他のメンバーを追加するときは、Webアプリの「データ管理」タブ →「権限管理（スタッフ権限）」から
    Googleアカウント・所属店舗・所属エリア・権限を登録する（マスタ権限のユーザーのみ操作できます）。

## Code.gs を修正したときの再デプロイ

Apps Scriptは保存しただけでは公開中のWebアプリに反映されません。**デプロイを管理 → 対象のデプロイの
鉛筆マーク → バージョン：新バージョン → デプロイ** まで行って初めて反映されます。

## CSVインポートの仕様

- `Utilities.parseCsv` でCSVを解析するため、ダブルクォートで囲まれたセル内のカンマ・改行にも対応しています。
- 文字コードは **UTF-8（BOM付き可）と Shift_JIS（CP932）の両方を自動判定**します。
  ブラウザでファイルを読み込む際にUTF-8として解釈できるかを判定し、できない場合はShift_JISとして読み込むため、
  業務システムから書き出したShift_JISのCSVもそのまま取り込めます。
- 見出し行は先頭5行の中から自動検出します（19項目のうち半分以上が一致した行を見出し行とみなします）。
- 19項目すべての値が完全に一致する行は「重複」として取り込まずスキップします。
  行の一部だけが違う場合（例：入金額だけ更新された等）は別行として追加されるため、
  必要に応じて「データ管理」タブの重複削除・全削除をご利用ください。
- `顧客ID` `予約番号` など先頭0を含みうる項目は、シート上で文字列（表示形式 `@`）として保存し、
  桁落ちしないようにしています。

## 実データの取り扱いについて（重要）

このリポジトリには、動作確認に使った実際の営業日報CSV（顧客ID・予約番号・担当者コードなどを含む）は
含めていません。取り込むCSVファイル自体もこのリポジトリには置かず、各自の権限管理下にあるGoogleドライブ /
スプレッドシートのみで扱ってください。`mockup/` 配下のサンプルデータもすべて架空の値です。
