# HIS WEDDING BATON 紹介コード自動発行システム

Googleフォームの回答をトリガーに、紹介コード（`BATON-000001` 形式の連番）を自動発行し、
スプレッドシートで管理しつつ、お客様へメールで案内するための追加GASです。

既存のアンケート送付処理（`sendSurveyEmails()` など）には一切手を加えません。
このフォルダの `ReferralCode.gs` を、既存のGoogle Apps Scriptプロジェクトに
「新しいファイルとして追加」するだけで動作します。

---

## できること

- フォーム回答時に、回答者のメールアドレスへ紹介コードを自動発行
- 同じメールアドレスで再回答しても、コードは再発行せず既存のものを返す
- 「紹介コード管理」シートを自動作成し、発行状況を一元管理
- 回答内容の控え＋紹介コードの案内をメールで送信
- 同時回答による連番の重複を`LockService`で防止

---

## 導入手順

### ステップ1. 既存のGASプロジェクトを開く

現在 `sendSurveyEmails()` が定義されているスクリプトエディタを開きます。
（Googleフォーム編集画面の右上「⋮」→「スクリプト エディタ」、
　またはフォームの回答が集まるスプレッドシートの「拡張機能」→「Apps Script」）

> ⚠️ どちらのプロジェクトに `sendSurveyEmails()` があるか不明な場合は、
> フォーム送信をトリガーにする都合上、**フォームの回答が集まるスプレッドシートに
> 紐づいた（container-bound）プロジェクト**に追加することを推奨します。

### ステップ2. ファイルを追加する

1. スクリプトエディタの左側「ファイル」の横にある「＋」→「スクリプト」をクリック
2. ファイル名を `ReferralCode` とする
3. このフォルダの `ReferralCode.gs` の中身を全てコピーして貼り付け、保存する

既存の `Code.gs`（`sendSurveyEmails()` が入っているファイル）はそのまま触りません。

### ステップ3. 設定項目を自分の環境に合わせて書き換える

`ReferralCode.gs` の冒頭にある `REFERRAL_CONFIG` を確認・編集します。

```js
const REFERRAL_CONFIG = {
  SHEET_NAME: '紹介コード管理',      // そのままでOK（自動作成されます）
  CODE_PREFIX: 'BATON-',
  CODE_DIGITS: 6,
  EMAIL_COLUMN_TITLE: 'メールアドレス', // ★回答シートの列見出しと一致させる
  NAME_COLUMN_TITLE: 'お名前',          // ★フォームの氏名質問のタイトルと一致させる
  ...
};
```

特に以下の2つは**必ず実際のフォーム・回答シートを見て確認**してください。

- `EMAIL_COLUMN_TITLE`
  フォームで「メールアドレスを収集する」設定を有効にしている場合、
  回答スプレッドシートに自動で「メールアドレス」という列が追加されます。
  列見出しが違う名前になっていたら、その名前に書き換えてください。

- `NAME_COLUMN_TITLE`
  フォーム内の「お名前」を尋ねる質問の**タイトル文言と完全に一致**させてください
  （1文字でも違うと取得できません）。

### ステップ4. 「紹介コード管理」シートを準備する

スクリプトエディタの関数選択プルダウンから `setupReferralSheet` を選び、実行（▶）します。
初回はGoogleアカウントへのアクセス許可を求められるので許可してください。

実行すると、回答シートと同じスプレッドシート内に
以下の見出しを持つ「紹介コード管理」シートが自動作成されます。

| 列 | 項目 |
|---|---|
| A | 紹介コード |
| B | メールアドレス |
| C | 氏名 |
| D | 発行日 |
| E | 紹介利用回数 |
| F | 紹介成立件数 |
| G | 紹介特典送付 |
| H | 利用者特典付与 |
| I | 備考 |

（このシートはフォーム回答時に自動作成もされるため、このステップは省略しても構いません。
　事前に見た目を確認したい場合のみ実行してください。）

### ステップ5. フォーム送信時トリガーを設定する

1. スクリプトエディタ左側の時計アイコン「トリガー」を開く
2. 右下「＋ トリガーを追加」をクリック
3. 以下のように設定する

   - 実行する関数を選択: `onFormSubmit`
   - 実行するデプロイを選択: `Head`
   - イベントのソースを選択: **スプレッドシートから**
   - イベントの種類を選択: **フォーム送信時**

4. 保存し、初回はアクセス許可（Gmail送信・スプレッドシート編集など）を承認する

> すでに同名の `onFormSubmit` トリガーが別の用途で存在する場合は、
> 関数名が重複しないよう `ReferralCode.gs` 側の関数名を変更するか、
> 既存のトリガー処理内からこのファイルの関数を呼び出す形に調整してください。

### ステップ6. テスト実行する

1. `ReferralCode.gs` 内の `testOnFormSubmit_` を実行してみる
   （ダミーのメールアドレス `test@example.com` 宛にテストメールが送信されます）
2. 実行ログ（表示 → ログ）でエラーが出ていないか確認する
3. 「紹介コード管理」シートに `BATON-000001` の行が追加されていることを確認する
4. 実際にGoogleフォームからテスト回答を送信し、一連の流れを確認する
   （同じメールアドレスで2回送信し、2回目も同じコードが返ることも確認してください）

## 送信されるメールの内容

件名:
```
【HIS WEDDING】アンケートのご回答ありがとうございました
```

本文には、フォームの回答内容の控え（質問と回答の一覧）に続けて、以下が追記されます。

```
━━━━━━━━━━━━━━━━━━
この度はアンケートへご回答いただき、
誠にありがとうございました。
あなた専用の紹介コードを発行いたしました。

【紹介コード】
BATON-000123

ご友人・ご家族へ
Instagram・LINEなどで自由にご紹介ください。

紹介コードをご利用いただき
ご来店・ご成約いただくと
ご紹介者様・ご利用者様双方へ
キャンペーン特典をプレゼントいたします。

紹介コードは大切に保管してください。
━━━━━━━━━━━━━━━━━━
```

> ※ Googleフォームの「回答のコピーを回答者に送信する」機能を
> すでに有効にしている場合、このメールとは別に、Google側の標準の
> 確認メールも送信されます（Apps Scriptからは内容を変更できないためです）。
> 二重送信を避けたい場合は、フォームの設定からその機能をオフにし、
> 今回追加した `sendCouponMail` に一本化することをおすすめします。

## エラー時の挙動

| 状況 | 挙動 |
|---|---|
| メールアドレス未入力 | 処理を終了（コード発行・メール送信ともに行わない） |
| コード発行に失敗 | ログに出力し、メールは送信しない |
| メール送信に失敗 | ログに出力するが、紹介コードはシートに保存されたまま残る |
| 同時回答による連番競合 | `LockService` により排他制御され、番号の重複は発生しない |

ログは Apps Script エディタの「実行数」または「ログ」から確認できます。
